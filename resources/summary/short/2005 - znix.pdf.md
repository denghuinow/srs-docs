# Short Summary: Project ZNIX

## Background and Objectives
Project ZNIX aims to refine traditional information management systems by providing an object-based, application-independent framework for retrieving and manipulating user information. The goal is to shift focus from mastering software applications to managing information based on its semantics, making it accessible in user-defined logical ways.

## In Scope
- Centralized storage for user information from specified third-party applications (e.g., email, documents, contacts).
- Hierarchical view of information, customizable by the user, displayed via a browser similar to Windows Explorer.
- Archiving of information to removable media (CD-ROMs, USB drives) with residual indicators in the data store.
- Public API for client processes to create, modify, and query Entities and relationships.
- Support for single-user mode on Windows 2000/XP without networking capabilities.

## Out of Scope
- Multi-user or networked operation at this development stage.
- Support for hardware interfaces beyond standard PC components.
- Communication interfaces (e.g., network protocols).
- Comprehensive user documentation; focus is on intuitive design.
- Licensing under proprietary terms; components use open-source licenses (LGPL/GPL).

## Stakeholders and Core Use Cases
**Stakeholders:**
- **End Users:** Home users, managerial staff, executives, and researchers with basic IT skills who interact with the Framework via GUIs.
- **Developers:** Third-party application developers who utilize the public API to build ZNIX-aware applications.
- **System Administrators:** Individuals responsible for deploying and maintaining the Framework on Windows systems.
- **Open Source Community:** Contributors and users who access, modify, and distribute the project under open-source licenses.

**Core Use Cases:**
1. As an end user, I want to view my information in a hierarchical browser so that I can navigate it intuitively like a file system.
2. As an end user, I want to archive information to removable media so that I can free up space while keeping track of archived items.
3. As an end user, I want to create relationships between documents and people so that I can organize information based on my own logic.
4. As a developer, I want to use a public API similar to .NET System.IO so that I can build applications that interact with the Framework easily.
5. As an end user, I want the Framework to capture emails and web documents automatically so that my information is centralized without manual effort.
6. As a system administrator, I want the Framework to run on low-resource systems so that it can be deployed on older hardware.

## Success Metrics
- Mean Time Between Failures (MTBF) exceeding 3 months.
- Framework Shell memory usage not exceeding 40 megabytes of RAM.
- User ability to perform basic tasks without training, leveraging familiar Windows-like GUIs.

## Major Constraints
- Hardware: Must run on Intel Pentium III or compatible 1-GHz PC with 256 megabytes of RAM.
- Operating System: Targeted for Windows 2000 Professional and Windows XP.
- Performance: Limited to single-user mode with no networking capabilities.
- Security: Must guard against malicious scripts and unintended user corruption of information.
- Compatibility: Assumes interfaces with specified third-party software remain compatible with subsequent releases.

## Undecided Issues
- Whether the browser GUI will be integrated directly into Windows Explorer or remain a standalone application.
- The extent of automation in data capturing and categorizing for building information hierarchies.
- Specific coding conventions to be documented before implementation.
- Potential new standards for ZNIX-aware client processes to conform to.
- The balance between non-technical help documentation and avoiding exhaustive user manuals.
