**Short Summary**

**Background and Objectives**  
The JSE, as the National Numbering Agent (NNA), must provide an automated system for issuing ISINs for Money Market Instruments (MMIs) to support the MMF’s electronic dematerialisation and same-day settlement initiative. The objective is to enable STRATE to electronically request, confirm, and cancel ISINs via SWIFT messages, ensuring immediate issuance for trading and settlement.

**In Scope**
- Automated issuance, cancellation, and deregistration of ISINs for MMIs using SWIFT MT598 messages.
- Support for four generic MMI categories with specific data fields (e.g., issue date, maturity, coupon rate).
- A front-end interface for monitoring, manual updates, and viewing ISIN statuses.
- Implementation of a Service Level Agreement (SLA) and Business Continuity Plan (BCP) with STRATE.
- Use of the ISIN prefix “ZAM” to distinguish MMIs from equities and bonds.

**Out of Scope**
- Manual issuance processes for equities or bonds (existing systems remain separate).
- Top-up or reduction of issued amounts (not required initially).
- Direct interaction with MMF participants (communication is only between JSE and STRATE).
- Changes to ANNA/ISO rules for ISIN issuance (existing rules apply).
- Development of STRATE’s internal MMI Engine or settlement systems.

**Stakeholders and Core Use Cases**  
*Stakeholders:*  
- **Money Market Forum (MMF):** Represents money market participants and defines business requirements.  
- **STRATE:** Acts as the Central Securities Depository (CSD) and requests ISINs via SWIFT.  
- **JSE (NNA):** Develops and operates the automated ISIN issuance system.  
- **JSE Application and Service Division (ASD):** Responsible for system development and maintenance.  
- **JSE Clearing & Settlement (C&S):** Manages operational monitoring and manual overrides.  
- **National Market Practice Group (NMPG):** Approves SWIFT message formats and content.  

*User Stories:*  
1. As STRATE, I want to request a new ISIN for an MMI via SWIFT so that the instrument can be dematerialised and settled electronically.  
2. As JSE (NNA), I want to automatically validate and issue an ISIN in response to a SWIFT request so that issuance is immediate and accurate.  
3. As STRATE, I want to cancel an ISIN for a de-issued MMI via SWIFT so that the instrument is removed from the system.  
4. As JSE C&S, I want to manually input ISINs during BCP events so that service continuity is maintained.  
5. As JSE C&S, I want to view and print daily issued/cancelled ISINs so that I can monitor system activity.  
6. As STRATE, I want to receive real-time rejections for invalid requests so that I can correct and resubmit messages promptly.

**Success Metrics**
- System processes 200–500 ISIN issuance requests per day without manual intervention.
- ISINs are issued and confirmed within minutes of a valid SWIFT request.
- All SWIFT message exchanges comply with approved MT598 formats and content.

**Major Constraints**
- Development costs must be recovered from STRATE, with monthly running costs defined in the SLA.
- The system must comply with ANNA and ISO rules for ISIN issuance.
- SWIFT message formats and content require approval from NMPG before implementation.
- The system must differentiate MMIs using the “ZAM” prefix and support four generic categories.
- A new SWIFT BIC branch code (“ISN”) is needed for correct routing and identification.

**Undecided Issues**
- Final error codes for SWIFT rejection messages (MT598-901/902) are yet to be defined between JSE and STRATE.
- The billing methodology for monthly running costs requires definition in the SLA.
- Updates to issuer codes via the front-end interface need clarification (referenced in email to STRATE).
- The handling of “issued amount” fields may default initially but requires future specification.
- Some MMI type codes (e.g., “NOTX” for Notes) require padding with ‘X’ characters, which may need further standardisation.
