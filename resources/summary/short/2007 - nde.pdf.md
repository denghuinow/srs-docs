# Short Summary: NDE System Requirements Specification

## Background and objectives
The NPOESS Data Exploitation (NDE) system will process and distribute environmental satellite data from NPP and NPOESS missions to NOAA's operational and climate communities. Its primary objectives are to generate tailored data products, archive NOAA-unique products, and provide customer services while ensuring data accessibility and system sustainability.

## In scope
- Receiving and processing xDRs from the IDPS interface
- Generating NOAA-unique and tailored data products in multiple formats (BUFR, GRIB2, netCDF, etc.)
- Distributing products to authorized users and archiving to CLASS
- Operating in Open, Degraded, and Restricted Access modes
- Monitoring system health and performance with automatic failover capabilities

## Out of scope
- Development of scientific algorithms (provided by NOAA)
- Satellite command and control functions
- Long-term archival beyond NOAA-unique products to CLASS
- Customer application development support
- Hardware manufacturing or procurement

## Stakeholders and core use cases
**Stakeholders:**
- NDE Project Manager: Oversees system development and contract compliance
- ESPC Operations: Manages daily system operations and interfaces
- NOAA Customers: Operational users receiving environmental data products
- System Operators: Monitor and maintain system performance
- Developers: Create and test algorithms and system elements
- CLASS Archive: Receives and preserves NOAA-unique products

**User stories:**
1. As a NOAA customer, I want to subscribe to tailored data products so that I receive timely environmental observations.
2. As a system operator, I want to monitor input data integrity so that I can ensure product quality.
3. As a developer, I want to test system elements without impacting operations so that I can validate new capabilities.
4. As an archive manager, I want to receive NOAA-unique products with manifests so that I can preserve them properly.
5. As a customer, I want to receive system status notifications so that I can plan my data usage.
6. As an operator, I want to adjust task priorities so that I can manage system resources during peak loads.

## Success metrics
- Product availability within 5 minutes of all required data receipt
- System availability exceeding 99% for ingest, generation, and distribution functions
- Successful delivery of 100% of SARSAT and A-DCS data within 1 minute of receipt

## Major constraints
- Must reuse existing hardware and software where practical and approved
- Must comply with Federal Enterprise Architecture and NOAA security standards
- Must support data volumes up to 8TB/day input and 16TB/day output
- Must operate within three environments: Operational, Development, and System Test
- Must maintain backward compatibility with IDPS interfaces

## Undecided issues
- Specific thresholds for data quality monitoring and reporting
- Detailed criteria for Restricted Access Mode authorization
- Final grid spacing specifications for tailored products
- Complete list of ancillary data sources beyond NCEP and NAVOCEANO
- Exact recovery time objectives for system restoration
