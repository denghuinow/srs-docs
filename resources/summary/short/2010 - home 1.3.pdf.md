# Short Summary: DigitalHome Software Requirements Specification

## Background and Objectives
The DigitalHome (DH) project aims to develop a prototype "Smart House" system for HomeOwner Inc., enabling remote management of home environmental controls, security, and appliances via a web interface. This prototype will inform future commercial development decisions by demonstrating core smart home capabilities in a simulated environment.

## In Scope
- Remote monitoring and control of temperature (60–80°F) via up to eight thermostats with scheduling capabilities.
- Humidity management (30–60%) via up to eight humidistats with programmable settings.
- Security system handling up to fifty contact sensors with light/sound alarm activation.
- Appliance management for up to one hundred power switches controlling lights and small appliances.
- Monthly planning and reporting features for environmental parameters and security events.

## Out of Scope
- Physical home implementation; all testing will occur in a simulated environment.
- Entertainment and communication system integration beyond basic appliance control.
- Support for non-web-based control interfaces (e.g., dedicated hardware panels).
- Integration with non-HVAC systems like irrigation or pool controls.
- Real-time video surveillance or advanced biometric security features.

## Stakeholders and Core Use Cases
**Stakeholders:**
- **General User:** Home resident who monitors and controls home devices via web interface.
- **Master User:** Designated user with configuration rights equivalent to a DH Technician.
- **DH Technician:** Trained professional responsible for system setup, maintenance, and configuration.
- **HomeOwner Inc. Management:** Decision-makers evaluating the prototype for commercial potential.
- **Development Team:** Engineers building the prototype under defined constraints.

**User Stories:**
1. As a General User, I want to adjust my home’s temperature remotely so that I can ensure comfort before arriving.
2. As a General User, I want to schedule humidity levels for different times so that I can maintain a healthy environment.
3. As a General User, I want to receive security breach alerts so that I can respond to potential intrusions.
4. As a Master User, I want to add new user accounts so that I can grant access to family members.
5. As a DH Technician, I want to configure system parameters so that I can optimize performance for each home.
6. As a General User, I want to generate monthly reports so that I can analyze energy usage and security events.

## Success Metrics
- System reliability with no more than one failure per 10,000 hours of operation.
- Completion of the functional prototype within the twelve-month development timeline.
- Effective simulation that adheres to real-world physical properties and constraints.

## Major Constraints
- Development limited to five engineers with a strict twelve-month deadline.
- Use of cost-minimized, widely available hardware/software technologies and standards.
- Mandatory adherence to HomeOwner Inc. development processes and documentation standards.
- All changes to requirements require approval from the DigitalHomeOwner Division Director.
- Object-oriented development using UML 2.0 is the preferred methodology.

## Undecided Issues
- Final selection of specific wireless communication protocols for device connectivity.
- Determination of exact backup mechanisms and schedules for user data.
- Specific security technology implementation details beyond Transport Layer Security.
- Detailed cost comparisons between DH components and competitive products.
- Long-term commercial product roadmap beyond the prototype evaluation phase.
