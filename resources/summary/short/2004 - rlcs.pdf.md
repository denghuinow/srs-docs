# Short Summary: I-15 Reversible Lane Control System (RLCS) Application Software Requirements

## Background and Objectives
The I-15 RLCS Application Software will replace an aging system to control reversible lanes during peak traffic and special events. Its primary objective is to safely open and close the reversible lanes while interfacing with new field hardware and providing data to external traffic management systems.

## In Scope
- Development of a new RLCS application software to monitor and control field devices (gates, pop-ups, CMS, lights).
- Implementation of a graphical user interface (GUI) for system status viewing, command issuance, and reporting.
- Integration with new field controllers and device I/O cards via driver software.
- Provision of system status data to external systems (ATMS, ValuePricing, ATIS) via an external server.
- Support for scheduled operations (opening/closing sequences) and system configuration.

## Out of Scope
- Hardware procurement and installation of field devices and controllers.
- Development of the underlying operating systems or database management systems (COTS to be used).
- Design of the physical communications network infrastructure.
- Manual field operations performed by maintenance staff without system intervention.
- Long-term data archival beyond the specified retention periods.

## Stakeholders and Core Use Cases
**Stakeholders:**
- **Operator:** Controls the system during normal mode and changes system mode.
- **Management:** Views reports and checks system status.
- **Field Maintenance Staff:** Controls the system during maintenance mode from field locations.
- **Electrical Systems Staff:** Checks hardware-related reports and status.
- **Software Systems Staff:** Checks software-related reports and status.
- **System Administrator:** Configures system data (staff, devices, schedules) and changes system mode.

**Core Use Cases:**
1. As an Operator, I want to issue control commands to open/close lanes so that traffic flow is managed during peak hours.
2. As a System Administrator, I want to configure user security levels and device rules so that system access and operations are secure.
3. As a Field Maintenance Staff member, I want to execute maintenance mode control sequences from remote terminals so that I can perform repairs without being onsite.
4. As Management, I want to generate historical operation reports so that I can analyze system performance and plan improvements.
5. As an Operator, I want to view real-time device status with alarms so that I can respond promptly to failures.
6. As an external system (e.g., ATMS), I want to retrieve RLCS lane status data so that I can integrate it into broader traffic management.

## Success Metrics
- System availability of 99.99% (approximately 50 minutes downtime per year).
- GUI status updates and alarm notifications within 2 seconds of occurrence.
- Successful execution of at least four daily scheduled opening/closing operations without critical failures.

## Major Constraints
- Must operate 24/7 with a recovery time of no more than 10 minutes after a failure.
- Must use commercial off-the-shelf software for database and reporting functions.
- Must adhere to strict safety rules to prevent simultaneous opening of opposite-direction entrances.
- Must support future roadway changes without requiring programming effort (configurable via tables).
- Communications between controllers must use wired connections (no wireless due to security).

## Undecided Issues
- Specific intelligent controller model to be used for field device interfacing.
- Final selection of COTS software for database and reporting (Oracle, Crystal Reports, etc., are preferred).
- Detailed validity checks for inputs and specific sequences for abnormal situations.
- Exact parameters for configurable time periods in override and halt scenarios.
- Final network communication rates and polling intervals may require adjustment based on hardware.
