# Short Summary: NLM Digital Repository Requirements

## Background and Objectives
The National Library of Medicine (NLM) requires a robust digital repository to acquire, organize, preserve, and provide access to biomedical digital materials, fulfilling its mission in the digital environment. The repository must support ingest, archival storage, data management, administration, preservation planning, and access functions based on the OAIS reference model.

## In Scope
- Digital collections under Library Operations responsibility, including PubMed Central, Bookshelf, and History of Medicine Division projects.
- Ingest of digitized and born-digital materials in approved formats (e.g., TIFF, PDF, XML).
- Long-term preservation and migration of digital objects to prevent obsolescence.
- Multiple user access levels (public, NIH staff, NLM staff) with appropriate restrictions.
- Metadata management supporting descriptive, administrative, and structural metadata.

## Out of Scope
- Digital projects not part of Library Operations’ collecting responsibility (e.g., UMLS, Visible Human).
- Web harvesting functionality (separate software will be used).
- Maintenance of special software for accessing materials (e.g., for audiovisuals).
- Materials with permanence ratings of "Permanence Not Guaranteed" may be removed under specific conditions.
- Offline delivery services; only online delivery is supported.

## Stakeholders and Core Use Cases
**Stakeholders:**
- **General Public:** End-users accessing materials, subject to licensing and copyright restrictions.
- **NIH Staff:** Researchers and employees using repository materials for work, with potential access restrictions.
- **NLM Staff (Metadata Access):** Catalogers and indexers adding or editing descriptive metadata without altering objects.
- **NLM Staff (Object Maintenance Access):** Specialists performing quality checks, format conversions, and system troubleshooting.
- **NLM System Administrators:** Personnel managing system configuration, security, and user access rights.
- **Content Producers/Donors:** Organizations or individuals submitting digital materials under negotiated agreements.

**Core Use Cases:**
1. As a content producer, I want to submit digital materials via FTP or physical media so that they are preserved and made accessible.
2. As a general public user, I want to search metadata and full text to find and view biomedical resources online.
3. As an NLM cataloger, I want to add descriptive metadata to digital objects so that they are discoverable and properly documented.
4. As an NLM preservation specialist, I want to monitor technology trends and develop migration plans so that digital objects remain accessible over time.
5. As a system administrator, I want to manage user access levels and audit system actions so that security and integrity are maintained.
6. As an NIH researcher, I want to access restricted materials from authorized locations so that I can use licensed content for my work.

## Success Metrics
- High availability and reliability of the repository system with minimal downtime.
- Successful ingestion and preservation of digital objects without data corruption.
- Compliance with OAIS standards and NLM policies for digital preservation.

## Major Constraints
- Integration with existing systems like PubMed Central and the Integrated Library System (ILS).
- Adherence to HHS/NIH security standards and compatibility with off-site backup facilities.
- Support for multiple languages and non-Roman scripts in ingest and access.
- Phased implementation due to budget and staff resource limitations.
- Acceptance of non-standard formats for historically important materials.

## Undecided Issues
- Specific migration strategies and methodologies for different digital formats.
- Detailed policies for ingest, including authorized staff and maximum embargo periods.
- Final metadata schema, potentially requiring updates to existing NLM standards.
- Decision-making process for adopting new repository standards and removing objects.
- Extent of federated searching across multiple NLM storage systems.
