# Short Summary: Automated Diagnostics Software Requirements Specification

## Background and Objectives
This document specifies requirements for an automated diagnostic tool that detects faults in HVAC subsystems (chillers, cooling towers, boilers) using pattern-recognition algorithms. The tool aims to replace manual visual analysis by automating expert diagnostic practices, providing building operators and service technicians with real-time fault detection and corrective guidance.

## In Scope
- Automated fault detection for chiller and cooling tower subsystems (initial version)
- Real-time and batch-mode data acquisition from sensors and files
- User interface with diagnostic browsing, configuration, and historical review
- Storage of diagnostic results with timestamps and metadata
- Support for both general users and administrator roles

## Out of Scope
- Manual data visualization or graphical analysis by human experts
- Diagnostic algorithms for HVAC subsystems beyond chillers and cooling towers in initial version
- User-defined custom analysis of diagnostic results
- Non-Windows operating system platforms
- Printed report generation (screen printing only)

## Stakeholders and Core Use Cases
**Stakeholders:**
- Building Operators: Monitor HVAC units from central control rooms
- Service Technicians: Perform on-site/off-site diagnostics during maintenance
- Energy Service Providers: Remotely monitor multiple customer facilities
- Operation Supervisors: Prioritize work assignments based on diagnostic results

**User Stories:**
1. As a building operator, I want to view current diagnostic results so that I can quickly assess equipment status.
2. As a service technician, I want to start/stop diagnostic processing so that I can analyze specific time periods.
3. As an administrator, I want to configure diagnostic parameters so that I can adjust sensitivity and equipment settings.
4. As an energy service provider, I want to browse historical diagnostics so that I can identify recurring issues.
5. As a general user, I want to authenticate with appropriate privileges so that I can access permitted functions.
6. As an operation supervisor, I want to print diagnostic information so that I can document findings for maintenance teams.

## Success Metrics
- Detection of specified chiller and cooling tower faults with associated causes and fixes
- Successful storage and retrieval of diagnostic results with complete metadata
- User ability to configure and adjust diagnostic sensitivity without software modification

## Major Constraints
- Must support users with varying computer expertise (from rudimentary to sophisticated)
- Restricted to Microsoft Windows-compatible operating systems
- Must handle both real-time data acquisition and batch file processing (not simultaneously)
- Design must allow for future addition of diagnostic algorithms for other HVAC subsystems
- Must operate continuously for indefinite periods when configured for monitoring

## Undecided Issues
- Procedures for deriving cooling tower approach benchmarks from performance data
- Development of chiller performance diagnostics (marked as placeholder for Round 2)
- Diagnostic procedures for ambient-temperature-based boiler shutoffs
- Methods for handling hot-water pump operation while boiler is off (safety concerns)
- Efficient algorithms for updating cycle counting variables in boiler diagnostics
