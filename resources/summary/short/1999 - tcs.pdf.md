# Short Summary: Tactical Control System (TCS) System/Subsystem Specification

## Background and Objectives
The Tactical Control System (TCS) is a joint-service command and control system designed to operate present and future tactical unmanned aerial vehicles (UAVs), including Predator (MAE) and Outrider (TUAV). Its primary objective is to provide a single, scalable system for UAV command, control, data receipt, processing, and dissemination, interoperable with joint C4I systems and supporting five levels of UAV interaction.

## In Scope
- Mission planning, control, monitoring, and payload product management for Predator and Outrider UAVs.
- Integration with specified C4I systems (e.g., AFATDS, ASAS, JSTARS) via defined interfaces.
- Support for five levels of UAV interaction, from data receipt to full flight control.
- Hardware and software meeting DII/COE compliance and open architecture standards.
- Training, maintenance, and logistics functions for system operators and maintainers.

## Out of Scope
- Nuclear safety requirements.
- Privacy requirements (tailored out as not applicable).
- Detailed internal data structures and processing algorithms (left to design specifications).
- Specific hardware components beyond defined COTS/NDI standards.
- Expansion on individual C4I interface protocols (covered in separate IDDs).

## Stakeholders and Core Use Cases
**Stakeholders:**
- **Program Executive Officer, Cruise Missiles Project and Unmanned Air Vehicles Joint Project:** Oversight and program management.
- **Naval Surface Warfare Center-Dahlgren Division and Joint Technology Center/System Integration Laboratory:** Development and engineering.
- **TCS Program Manager and Deputy Program Manager:** Program execution and approval.
- **Integrated Product Teams (IPTs) (e.g., C4I, Software, System Test):** Specific domain responsibility.
- **Warfighters Planning Group:** Operational requirements and user representation.
- **Service Operators (Army, Marine Corps, Air Force):** End-users operating UAVs in tactical environments.

**Core Use Cases:**
1. As a UAV operator, I want to plan and upload flight routes with terrain avoidance so that the UAV can execute reconnaissance missions safely.
2. As a payload operator, I want to control and monitor EO/IR/SAR sensors in real-time so that I can acquire and identify targets.
3. As a mission commander, I want to disseminate NITF 2.0 imagery and tactical messages to C4I systems so that intelligence is shared across the joint force.
4. As a maintenance technician, I want to perform fault detection to the LRU level so that system readiness is maintained.
5. As a training supervisor, I want to use embedded interactive courseware so that operators can practice without live UAVs.
6. As a system administrator, I want to install software upgrades via CD-ROM with password protection so that system capabilities are updated securely.

## Success Metrics
- System availability (Ao) equal to or greater than Predator and Outrider ORD thresholds.
- Mission planning and launch within 1 hour of tasking after emplacement.
- Successful interoperability with all specified C4I systems per the integration schedule.

## Major Constraints
- Must use DII/COE-compliant, non-proprietary software and COTS/NDI hardware where possible.
- Must support five levels of UAV interaction, restricting unauthorized access via configuration.
- Must achieve Year 2000 compliance for all hardware and software components.
- Must operate within specified environmental conditions for land-based shelter and shipboard use.
- Must comply with MIL-STD-498 for documentation and MIL-STD-882C for safety.

## Undecided Issues
- Specific electromagnetic environment values for operational compatibility (to be determined in Phase I).
- Radar cross-section analysis and UAV signature versus threat lookup table completion (pending government characterization).
- Objective capabilities for integration onto submarines and ships (noted as objectives).
- Full implementation schedule for all C4I interfaces beyond priority systems (see Table 3.3.1.1-1).
- Risk levels and hazard management program details (to be developed in Phase I).
