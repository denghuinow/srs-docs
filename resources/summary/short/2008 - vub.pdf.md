**Short Summary**

**Background and objectives**  
The Publications Management System (PMS) is a web‑based platform designed to manage a database of academic publications, supporting upload, search, and download functionalities. It aims to provide controlled access to bibliographical information and full‑text documents for users within the VUB network and registered members.

**In scope**  
- Web and command‑line interfaces for system access.  
- User registration, login, and role‑based privileges (Guest, VUB‑Network User, Member, Publisher, Moderator, Administrator).  
- Publication search, viewing, and download in formats such as PDF and PostScript.  
- Upload and editing of publications with automatic metadata extraction.  
- User and group management by administrators and moderators.

**Out of scope**  
- Support for additional document formats (e.g., MS Word) beyond PDF, PostScript, BibTeX, and RIS.  
- Automatic recognition of author/institute aliases (e.g., “D. Vermeir” vs. “Dirk Vermeir”).  
- Integration of audio or video file management.  
- Automated retrieval of full texts from URLs in uploaded abstracts.  
- Expansion to non‑academic or external user bases beyond the VUB network.

**Stakeholders and core use cases**  
*Stakeholders*  
- **Guest**: Anonymous user outside the VUB network; can only register or log in.  
- **VUB‑Network User**: User connected to the VUB network; can search and download publications.  
- **Member**: Logged‑in user; can search, download, and manage personal account details.  
- **Publisher**: Logged‑in user; can upload, edit own publications, and perform bulk uploads.  
- **Moderator**: Logged‑in user; can manage user levels, group permissions, and edit departmental publications.  
- **Administrator**: Logged‑in user; has full system control, including user/group creation/deletion and system configuration.  

*Core use cases*  
1. As a Guest, I want to register for an account so that I can access the system as a Member.  
2. As a VUB‑Network User, I want to search for publications by keyword or author so that I can find relevant academic works.  
3. As a Member, I want to download multiple publications so that I can obtain full‑text copies for research.  
4. As a Publisher, I want to upload a publication in BibTeX format so that its metadata is automatically extracted and stored.  
5. As a Moderator, I want to edit departmental publication details so that bibliographical information remains accurate.  
6. As an Administrator, I want to create or delete user accounts so that I can manage system access and privileges.

**Success metrics**  
- System availability exceeding 99% during operational hours, barring Wilma server downtime.  
- Successful upload and automatic metadata extraction for at least 95% of submitted publications.  
- User satisfaction score of at least 4/5 on ease of search and download functionality.

**Major constraints**  
- Must run on the Linux‑based Wilma server at VUB.  
- Web interface must comply with W3C XHTML 1.0 Transitional standards.  
- Implementation must use Ruby without frameworks, with code documented via RDoc.  
- Only free software tools and libraries are permitted.  
- Design must be modular to facilitate future expansions.

**Undecided issues**  
- Maximum file size for uploaded publications remains to be determined.  
- Performance requirements (e.g., response times, concurrent user handling) are still TBD.  
- The exact installation procedure for the PMS is not yet finalized.  
- Support for additional export formats beyond HTML, PDF, and PS is under consideration.  
- Enhancement of the control panel functionalities for administrators is pending further specification.
