# Short Summary: APAF Software Requirements Specification

## Background and Objectives
The APAF ground data system will process ASPERA-3 instrument telemetry and Mars Express orbit/attitude data into IDFS datasets for scientific analysis and archiving. Its primary objectives are to support the ASPERA-3 science team during mission operations and to deliver validated, PDS-compliant data to NASA within six months of acquisition.

## In Scope
- Acquisition and processing of ASPERA-3 telemetry and Mars Express orbit/attitude data into IDFS datasets.
- Storage of telemetry and IDFS data on a local SwRI archive.
- Provision of web-based displays for public viewing and password-protected science analysis.
- Distribution of IDFS data and processing software to ASPERA-3 Co-Investigators.
- Submission of calibrated ASPERA-3 data to NASA's Planetary Data System (PDS).

## Out of Scope
- Operation in multiple states or modes.
- Installation-dependent adaptation requirements.
- Safety requirements (no hazards posed).
- Specific software quality factor requirements.
- Training requirements for developers or users.

## Stakeholders and Core Use Cases
**Stakeholders:**
- **SwRI Principal Investigator:** Oversees scientific integrity and project direction.
- **IRF Principal Investigator:** Leads the ASPERA-3 experiment and science team.
- **IRF Project Manager:** Manages project execution and coordination with ESA.
- **SwRI Software Project Manager:** Directs APAF software development and delivery.
- **ASPERA-3 Co-Investigators:** Analyze processed data to meet mission science goals.
- **ESA/ESOC:** Provides telemetry data and mission operations support.

**Core Use Cases:**
1. As a system operator, I want to automatically acquire telemetry from ESOC daily so that data processing can begin promptly.
2. As a scientist, I want ASPERA-3 data processed into IDFS datasets so that I can perform scientific analysis.
3. As a data manager, I want telemetry and IDFS data stored locally so that it is available for reprocessing and analysis.
4. As a public outreach coordinator, I want web-based displays of current data so that the public can monitor instrument performance.
5. As a Co-Investigator, I want password-protected access to all ASPERA-3 data via web displays so that I can conduct science analysis before data is public.
6. As an archivist, I want to submit calibrated ASPERA-3 data to PDS within six months so that it is available to the broader scientific community.

## Success Metrics
- ASPERA-3 IDFS data delivered to Co-Investigators within 24 hours of error-free telemetry acquisition.
- Calibrated ASPERA-3 data submitted to NASA PDS no later than six months after acquisition.
- Web-based displays operational for public viewing and science team analysis.

## Major Constraints
- Must interface with ESOC's Data Disposition System via NISN for telemetry acquisition.
- Data processing algorithms must be delivered to IRF to support Mars Express launch and operations.
- System must operate on UNIX-based development and production computers.
- Distribution mechanisms for Co-Investigators must be finalized six months prior to Mars Express launch.
- All software and data delivery must comply with NASA Discovery Program requirements.

## Undecided Issues
- Specific distribution mechanisms and exact datasets for each Co-Investigator will be determined six months before launch.
- Any installation-dependent adaptation requirements will be documented in the Operations Procedures Document if identified.
- The precedence and criticality of requirements may need special consideration later.
