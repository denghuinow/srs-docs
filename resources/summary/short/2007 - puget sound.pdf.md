# Short Summary: Puget Sound Moodle Enhancements

## Background and Objectives
The University of Puget Sound seeks to enhance Moodle as a potential replacement for Blackboard, addressing critical educational needs through targeted feature development. The project aims to improve the learning experience by implementing missing functionality identified through stakeholder interviews.

## In Scope
- Multiple file upload capability configurable per page (e.g., assignments, forums)
- Audio recording and portfolio management for language learning
- Search functionality across course pages with filtering options
- Gradebook with grading, feedback, and history tracking
- Web feeds (RSS) configurable per page for content updates

## Out of Scope
- Complete replacement of Moodle's social/collaborative components
- Development of entirely new courseware system architecture
- Modification of core Moodle APIs beyond enhancement boundaries
- Integration with third-party social networking services
- Comprehensive redesign of all existing Moodle user interfaces

## Stakeholders and Core Use Cases
**Stakeholders:**
- **Students:** Primary consumers who access content, submit assignments, and participate in discussions
- **Professors:** Primary content administrators who upload materials, create activities, and grade assignments
- **System Administrators:** Technical staff responsible for system maintenance, configuration, and updates

**User Stories:**
1. As a professor, I want to enable multiple file uploads on assignment pages so that students can submit multi-part projects
2. As a language student, I want to record and organize voice clips in a portfolio so that I can track my speaking progress over time
3. As a student, I want to search across all course pages so that I can quickly find assignments and materials
4. As a professor, I want to provide RSS feeds for course announcements so that students receive timely updates
5. As a professor, I want to grade assignments online with feedback so that students receive prompt evaluation
6. As a system administrator, I want configurable backup schedules so that course data is protected reliably

## Success Metrics
- System supports 1,000 concurrent users during peak periods (midterms/finals)
- System achieves 99% uptime with 24/7 availability expectation
- Core Priority 1 and 2 requirements implemented in initial release

## Major Constraints
- Must utilize existing Moodle APIs without substantial core modification
- Limited Office of Information Services staff requires system to be largely self-sustaining
- Must maintain compatibility with University practices and standards
- Development timeline and budget limit Priority 3 requirement implementation
- Must provide simple, responsive interface despite diverse system components

## Undecided Issues
- Specific implementation approach for wiki and blog integration (Priority 3)
- Final determination of Moodle adoption versus other courseware solutions
- Exact backup frequency and off-site storage requirements
- Detailed notification subscription management interface design
- Comprehensive user documentation development approach
