# Balanced Summary: Tactical Control System (TCS) Block 0

## Goals and Scope
The Tactical Control System (TCS) is a joint-service command and control system designed to operate present and future tactical unmanned aerial vehicles (UAVs), including the Predator (MAE) and Outrider (TUAV). Its primary purpose is to provide a single, scalable system for mission planning, execution, data receipt, processing, and dissemination, interoperable with a wide array of C4I systems. The system is developed in phases, with an emphasis on an open, DII/COE-compliant software architecture and the use of commercial and government off-the-shelf hardware where possible.

## Stakeholders and User Stories
*   **Program Executive Officer, Cruise Missiles Project and Unmanned Air Vehicles Joint Project:** Oversees the overall TCS program and ensures it meets joint-service operational needs.
*   **Naval Surface Warfare Center-Dahlgren Division (NSWCDD):** Co-preparer of the specification; responsible for system development and engineering.
*   **Joint Technology Center/System Integration Laboratory, U.S. Army Missile Command:** Co-preparer of the specification; responsible for system integration and laboratory functions.
*   **TCS Program Manager:** Ultimately approves the system specification and manages program execution.
*   **Integrated Product Teams (IPTs - C4I, CM, Data Links, Logistics, RAD, Software, etc.):** Represent various technical and support disciplines responsible for specific subsystem development and integration.
*   **Warfighters Planning Group:** Represents the end-user operational perspective to ensure the system meets tactical requirements.

**User Stories:**
1.  As a **UAV Operator**, I want to **control multiple UAVs and their payloads from a single workstation** so that **I can efficiently conduct reconnaissance and surveillance missions**.
2.  As a **Mission Planner**, I want to **import, create, and modify flight and payload plans using graphical tools and map overlays** so that **I can prepare effective and survivable missions**.
3.  As an **Imagery Analyst**, I want to **receive, process, annotate, and disseminate near-real-time EO/IR/SAR imagery in standard formats** so that **time-sensitive intelligence can be provided to command and weapon systems**.
4.  As a **System Maintainer**, I want to **execute built-in diagnostics and software upgrades via authorized access** so that **I can keep the system operational with minimal downtime**.
5.  As a **Battlefield Commander**, I want the **TCS to interface seamlessly with my C4I systems (e.g., AFATDS, JSTARS)** so that **UAV-derived data is integrated into the common operational picture**.
6.  As a **Training Officer**, I want to **use embedded interactive training software** so that **operator and maintainer proficiency can be sustained without using operational assets**.

## Key Processes
1.  **System Startup (Trigger: Application of power):** The system initializes hardware and software, performs fault detection, and determines the achievable level of UAV interaction.
2.  **Mission Planning (Trigger: Receipt of tasking order):** The operator creates or modifies flight routes, payload plans, and communication plans using interactive map displays and validation tools.
3.  **Mission Upload & Execution (Trigger: Operator command):** Validated mission plans are uploaded to the UAV, which is then controlled and monitored via line-of-sight or satellite data links.
4.  **Payload Data Management (Trigger: Receipt of downlinked data):** Imagery and telemetry data are processed, displayed, annotated, stored, and prepared for dissemination.
5.  **C4I Interface & Dissemination (Trigger: Data ready or incoming message):** The system exchanges tactical messages, imagery, and video with external command, control, and intelligence systems.
6.  **System Maintenance & Recovery (Trigger: Scheduled maintenance or fault detection):** Authorized personnel perform diagnostics, software updates, and component maintenance.
7.  **System Shutdown (Trigger: Operator command):** The system safely terminates functions, stores or deletes data as directed, and prepares for power removal.

## Domain Data Elements
*   **Mission Plan**
    *   **Primary Key:** Plan ID / Name
    *   **Key Fields:** Associated UAV Type, Flight Route (Waypoints), Payload Tasking, Communications Settings, Validity Status
*   **Air Vehicle (AV)**
    *   **Primary Key:** AV Tail Number / Identification
    *   **Key Fields:** Current Status (Location, Altitude, Heading), Telemetry Data, Fuel State, Active Mission Plan
*   **Payload Product**
    *   **Primary Key:** Imagery/Data File ID
    *   **Key Fields:** Sensor Type (EO/IR/SAR), Collection Timestamp, Geospatial Coordinates, Exploitation Annotations, Dissemination Format (e.g., NITF 2.0)
*   **Target**
    *   **Primary Key:** Target Designation
    *   **Key Fields:** Coordinates (Lat/Lon, MGRS), Location Error Estimate, Type, Associated Imagery
*   **C4I Message**
    *   **Primary Key:** Message ID
    *   **Key Fields:** Message Format (e.g., USMTF, VMF), Source/Destination System, Content, Transmission/Receipt Time
*   **System Configuration**
    *   **Primary Key:** Configuration Profile Name
    *   **Key Fields:** Available UAV Types, Enabled C4I Interfaces, Authorized Interaction Levels, Map Data Sets

## Non-Functional Requirements
1.  **Performance:** System throughput shall not exceed 50% of capability over any 10-second period (25% objective).
2.  **Reliability & Availability:** Shall achieve Mean Time Between Failure (MTBF), Mean Time To Repair (MTTR), and Availability (Ao) equal to or greater than thresholds specified in the Predator and Outrider ORDs.
3.  **Security:** Must comply with DoD security directives (DoDD 5200.28), be accreditable for processing classified data, and secure all communications links appropriately.
4.  **Usability:** The Human-Computer Interface (HCI) shall be a graphical, X-windows/Motif-based system operable by 5th percentile female to 95th percentile male personnel in mission-oriented protective posture.
5.  **Portability & Flexibility:** Software shall be DII/COE and JTA compliant, non-proprietary, and hostable on various Service-specific hardware. The architecture must support future UAVs and payloads.
6.  **Environmental:** Hardware must be ruggedized for transport and operate within specified land-based shelter and shipboard environments.

## Milestones and External Dependencies
1.  **Phase 1 (Program Definition and Risk Reduction):** 24-month period to demonstrate Levels 1-5 UAV interaction.
2.  **Phase 2 (Engineering and Manufacturing Development):** Includes commencement of Low Rate Initial Production (LRIP).
3.  **C4I Interface Integration Schedule:** Prioritized implementation of interfaces with systems like AFATDS, ASAS, and JSTARS as defined in a JROC-validated schedule.
4.  **Dependency on UAV OEMs:** Relies on Original Equipment Manufacturers for AV-specific maintenance software and data link interfaces.
5.  **Dependency on NIMA:** Requires National Imagery and Mapping Agency for digital terrain, feature, and map data (DTED, DFAD, ADRG).

## Risks and Mitigation Strategies
1.  **Risk:** Integration complexity with numerous, diverse C4I systems.
    *   **Mitigation:** Follow a prioritized integration schedule and leverage DII/COE common message processors and standard interfaces.
2.  **Risk:** Ensuring safety of flight and avoiding unsafe commands to UAVs.
    *   **Mitigation:** Design with no single-point hardware/software failure leading to unsafe commands, implement automatic mission plan validation, and provide clear operator cautions/warnings.
3.  **Risk:** Achieving required system performance (latency, throughput) with scalable, COTS-based hardware.
    *   **Mitigation:** Define strict resource utilization thresholds (50% CPU, 50% memory spare) and design for distributed processing.
4.  **Risk:** Meeting stringent security accreditation requirements for a system interfacing with multiple classification levels.
    *   **Mitigation:** Base security requirements on risk assessment of interfaced systems, implement password protection, and plan for a tailored training program.
5.  **Risk:** Managing conflicting requirements between different UAV ORDs (Predator vs. Outrider) and referenced documents.
    *   **Mitigation:** Establish a clear precedence order (TCS ORD > TCS SSS > other docs) and a process for conflict resolution with the procuring agency.

## Undecided Issues
1.  Specific electromagnetic environment (EMI/RADHAZ) values for different service operational environments.
2.  Final determination of special tools and test equipment (SPTE) required for maintenance.
3.  Complete list of specific tactical message types for each C4I interface (to be defined in individual Interface Design Descriptions).
4.  Detailed human factors engineering specifications beyond compliance with MIL-STD-1472 (referenced to a separate HCI Spec, TCS 108).
5.  Formal training program structure and requirements for Phase 2 and beyond.
6.  Specific logistics and support requirements for Phase 2 (LRIP), to be developed based on Phase 1 findings.
