# Detailed Summary: Tactical Control System (TCS) Block 0

## Background and Scope
The Tactical Control System (TCS) is a joint-service command, control, data receipt, processing, export, and dissemination system designed to be interoperable with present and future tactical unmanned aerial vehicles (UAVs), including the Predator (MAE) and Outrider (TUAV). Its purpose is to provide a common human-computer interface to simplify operations, training, and integration into joint C4I infrastructure. The system is developed in two phases: Phase 1 (Program Definition and Risk Reduction) and Phase 2 (Engineering and Manufacturing Development). Non-goals include not supporting formal training concurrent with actual missions and not requiring nuclear safety considerations.

## Stakeholders Matrix and Use Cases
*   **UAV Operators:** Control and monitor UAVs and payloads during mission execution.
*   **Mission Planners:** Generate, modify, and validate UAV mission plans, including flight routes and payload tasks.
*   **Maintenance Personnel:** Perform fault detection, location, and software/hardware maintenance on TCS components.
*   **C4I System Operators:** Receive and process UAV-derived data (imagery, target coordinates) from TCS for tactical decision-making.
*   **Training Personnel:** Use the system in training mode to instruct operators without interfering with live operations.
*   **System Administrators/Authorized Operators:** Install software upgrades, modify programmable parameters, and perform software debugging.
*   **Program Management (UAV JPO, NSWCDD, SIL):** Oversee TCS development, integration, and compliance with requirements.
*   **Security Personnel:** Ensure the system meets physical, communications, and computer security standards for processing classified data.

**Main Scenarios:**
1.  **Normal Mission Execution:** Operator plans a mission, uploads it to a UAV, controls the flight and payload in real-time, processes received imagery, and disseminates products to C4I systems.
2.  **Loss of Link (LOL) Handling:** System detects loss of downlink, initiates LOL timer, computes estimated UAV position, and attempts re-establishment.
3.  **Mission Handover:** Control of a UAV is seamlessly passed from one TCS to another.
4.  **Concurrent Control of Two UAVs:** Operator manages two Medium Altitude Endurance (MAE) UAVs beyond line of sight using sequential communications.
5.  **System Startup/Recovery:** System initializes hardware/software, performs fault detection, and enters operations state within 60 seconds (normal) or 45 seconds (recovery).
6.  **Training Mode Operation:** Personnel conduct simulated mission planning and execution without interfacing with live assets (except for identified training messages).
7.  **Maintenance Mode Operation:** Technician runs diagnostics on AV, payload, data terminal, or workstation components and performs software upgrades.
8.  **Dynamic Retasking:** During flight, operator modifies the UAV's flight path or payload tasking based on new intelligence.

## Business Process
**Main Process: Execute UAV Mission (Normal Operations Mode)**
1.  **Trigger:** Receipt of mission tasking order via C4I interface.
2.  **Input:** Tasking order, map/terrain data, threat data.
3.  **Step 1 (Plan):** Operator creates/retrieves mission plan (flight route, payload plan, comms plan) using graphical tools and validates it.
4.  **Step 2 (Upload):** Validated mission plan is uploaded to the selected UAV via data link.
5.  **Step 3 (Launch/Monitor):** Operator initiates launch (if Level 5) and monitors UAV telemetry, position, and system status against the plan.
6.  **Step 4 (Control):** Operator manually controls or adjusts UAV flight and payload sensor pointing as required.
7.  **Step 5 (Process):** System receives, processes, stores, and displays payload (EO/IR/SAR) imagery and data.
8.  **Step 6 (Exploit/Disseminate):** Operator performs limited image exploitation (annotation, enhancement) and disseminates products (NITF files, video, messages) to designated C4I systems.
9.  **Step 7 (Recover):** Operator initiates and monitors UAV recovery and landing.
10. **Output:** Mission products disseminated, mission data archived, UAV recovered.

**Key Branch A: Loss of Link (LOL)**
1.  **Trigger:** Loss of downlink telemetry.
2.  **Step 1:** System initiates LOL timer and displays last known UAV status.
3.  **Step 2:** System computes estimated UAV position based on last known state and flight plan.
4.  **Step 3:** System attempts to re-establish the data link.
5.  **Step 4:** If timer expires, UAV executes pre-programmed LOL procedures (e.g., return to base).

**Key Branch B: Mission Plan Validation Failure**
1.  **Trigger:** Automated pre-flight check detects constraint violation (e.g., altitude, fuel, threat zone).
2.  **Step 1:** System notifies operator of discrepancies.
3.  **Step 2:** Operator reviews faults.
4.  **Step 3:** Operator can choose to override faults after acknowledgment or modify the plan.

## Domain Model
*   **Mission Plan:** (Required) Includes unique name, associated AV, flight route plan, payload plan, communications plan.
*   **Air Vehicle (AV):** (Required) Has type (e.g., Predator, Outrider), unique identification, current state (telemetry, position, fuel), and supports specific levels of interaction.
*   **Payload:** (Required) Has type (EO, IR, SAR), mode, current field of view/footprint, and status.
*   **Data Terminal (DT):** (Required) Includes antenna (pointing, mode) and transmitter/receiver (frequency, power) control elements.
*   **Waypoint:** (Required, reference to Mission Plan) Contains geographic coordinates, altitude, airspeed.
*   **Target:** (Required) Has geographic coordinates, type, estimated accuracy, and associated imagery/product.
*   **C4I Interface Connection:** (Required) Defines connected external system (e.g., AFATDS, JSTARS), status (online/offline), and supported message types.
*   **Imagery Product:** (Required) Includes source payload, timestamp, raw/processed data, annotation, and format (e.g., NITF 2.0).

## Interfaces and Integrations
1.  **AV Standard Interface:** TCS -> AV. Bidirectional. Uplink commands and downlink telemetry/imagery. Key Points: Concurrent uplink/downlink, supports multiple AV types via generic architecture.
2.  **Data Terminal Control:** TCS -> Data Terminal (LOS/SATCOM). Bidirectional. Control and status monitoring. Key Points: Simultaneous LOS & SATCOM support, automatic/manual antenna and frequency control.
3.  **C4I Digital Interface (e.g., AFATDS, ASAS):** TCS <-> C4I Systems. Bidirectional. Exchange of tactical messages (USMTF, VMF) and digital imagery (NITF). Key Points: Uses DII/COE UCP/CMP, error checking, message logging.
4.  **C4I Analog Interface (e.g., CCTV):** TCS -> C4I Systems. TCS output. Distribution of RS-170A video with/without overlay.
5.  **External Data Storage:** TCS <-> Storage Devices. Bidirectional. Import/export of mission plans, map data, and imagery products. Key Points: Supports CD-ROM, tape, RAID.
6.  **Printer:** TCS -> Printer. TCS output. Hard copy of freeze-frame imagery, messages, mission plans, and map displays.
7.  **Intercom System:** TCS <-> Internal. Bidirectional. Voice communication between multiple operators within the TCS.
8.  **Real-Time Processor (RTP)/Data Server:** TCS Internal. Bidirectional. Distributes real-time data (e.g., from data server) to other TCS software components to support distributed processing.

## Acceptance Criteria
**Capability: Mission Planning & Validation**
*   **Given** a set of flight waypoints that violate the UAV's altitude constraints,
*   **When** the operator requests mission plan validation,
*   **Then** the system shall notify the operator of the altitude fault and prevent upload until the fault is acknowledged and overridden.

**Capability: Payload Control & Imagery Display**
*   **Given** a UAV is on station and streaming EO/IR video,
*   **When** the operator selects a point on the live video display,
*   **Then** the system shall calculate and display the geographic coordinates of that point and allow the operator to annotate the imagery.

**Capability: Loss of Link Handling**
*   **Given** the UAV is in autonomous flight and the downlink is lost,
*   **When** the LOL timer expires,
*   **Then** the system shall display the estimated UAV position based on its last known state and flight plan and indicate execution of LOL procedures.

**Capability: C4I Interoperability**
*   **Given** a target coordinate has been developed within the TCS,
*   **When** the operator initiates a send to the Advanced Field Artillery Tactical Data System (AFATDS),
*   **Then** the system shall format and transmit a compliant Variable Message Format (VMF) message to AFATDS and log the transaction.

## Non-functional Metrics
*   **Performance:** System throughput shall not exceed 50% of capability over any 10-second period. Operator command to system acknowledgment response time ≤ 1 second.
*   **Reliability/Availability:** Achieve Mean Time Between Failures (MTBF), Mean Time To Repair (MTTR), and Operational Availability (Ao) equal to or greater than thresholds specified in the Predator and Outrider ORDs.
*   **Security:** System shall be accredited per DoD Directive 5200.28(D). All external communications links shall be secured per the sensitivity of transmitted data.
*   **Compliance:** Software shall be DII/COE and JTA compliant. Hardware/software shall be Year 2000 compliant.
*   **Observability:** System shall record all operator inputs, warning messages, and interface communications to support event reconstruction and performance analysis.

## Milestones and Release Strategy
1.  **Phase 1 Completion (Program Definition & Risk Reduction):** Demonstrate Levels 1-5 interaction in an incremental strategy over 24 months.
2.  **C4I Interface Rollout:** Implement interfaces per priority schedule (e.g., AFATDS, ASAS in FY97; others through FY01).
3.  **Low Rate Initial Production (LRIP) Start:** Commence during Phase 2 (Engineering and Manufacturing Development).
4.  **Initial Operational Test & Evaluation (IOT&E):** Conduct with verified and validated operator and technical manuals.
5.  **Fielding to Services:** Deploy scaleable configurations to Army, Marine Corps, and Air Force units as an organic component of their UAV systems.
6.  **Future Capability Integration:** Incorporate support for future UAVs, payloads (e.g., auto-search), and platforms (ships, submarines, aircraft) as objectives.

## Risk List and Mitigation Strategies
1.  **Risk:** Integration complexity with numerous, diverse C4I systems.
    *   **Mitigation:** Follow prioritized integration schedule; leverage DII/COE GOTS software (UCP/CMP) for common interfaces.
2.  **Risk:** Ensuring real-time performance and data latency meets requirements for controlling multiple UAVs.
    *   **Mitigation:** Design with 50% throughput reserve; use distributed processing architecture; prototype and test with 6-DOF simulators.
3.  **Risk:** Achieving common HCI and interoperability across different UAV types (Predator, Outrider).
    *   **Mitigation:** Develop core generic software with AV-specific modules; use open, modular architecture; conduct operator evaluations.
4.  **Risk:** System safety – preventing single-point hardware/software failures from causing unsafe UAV commands.
    *   **Mitigation:** Incorporate design safeguards, rigorous testing, and independent verification and validation (IV&V) of safety-critical components.
5.  **Risk:** Meeting stringent security accreditation requirements for processing and disseminating classified data.
    *   **Mitigation:** Early engagement with Designated Approving Authority (DAA); risk assessment per DoD 5200.28(D); use of NSA-approved encryption.
6.  **Risk:** Logistics and maintainability across different military services.
    *   **Mitigation:** Maximize use of COTS/NDI hardware and standard DoD tools/TMDE; design with LRU and embedded diagnostics.
7.  **Risk:** Physical and electromagnetic environmental survivability in tactical deployments.
    *   **Mitigation:** Design to specified shelter/shipboard environments; apply EMI control techniques during design; test in representative environments.
8.  **Risk:** Successful development and integration of training capabilities.
    *   **Mitigation:** Develop interactive courseware during Phase 1; gather feedback from demonstrations; ensure training software is isolated from operational software.
