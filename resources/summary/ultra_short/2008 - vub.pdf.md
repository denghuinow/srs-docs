**Purpose & Scope**
The system is a Publications Management System (PMS) for managing a database of bibliographic information and full-text publications. It provides search, download, and upload capabilities with access control. It does not handle audio or video files.

**Product Background / Positioning**
The PMS is a standalone system for academic use at the Free University of Brussels (VUB). It will be deployed on the existing 'Wilma' Linux server and must integrate with a MySQL database and a web server.

**Core Functional Overview**
1.  Search publications by criteria like keyword, author, and date.
2.  View and download publication details and full texts.
3.  Upload publications, with automatic extraction of bibliographic data from PDF/PS files.
4.  Manage user accounts and permissions across different privilege levels.
5.  Administer system configuration, user groups, and all publication data.

**Key Users & Usage Scenarios**
*   **Guest:** Can only register or log in.
*   **VUB-Network User:** Identified by IP; can search and download without logging in.
*   **Member:** Logged-in user with search/download rights.
*   **Publisher:** Can upload and edit their own publications.
*   **Moderator:** Can edit publications within their assigned department/group.
*   **Administrator:** Has full system control, including user/group management and editing any publication.
A typical scenario involves a researcher searching for publications, downloading relevant ones, and uploading their own work.

**Major External Interfaces**
*   **User Interface:** A web interface accessible via standard browsers, compliant with W3C XHTML.
*   **System Interface:** Interfaces with a MySQL database and a web server.
*   **Communication Interface:** HTTP over TCP/IP port 80.
*   **Command Line Interface:** For administrators with local server access.

**Key Non-functional Requirements**
*   **Security:** User passwords must be encrypted in transit and in storage. Access control must enforce the defined user privilege hierarchy.
*   **Availability:** The system must be available whenever the Wilma server is available.
*   **Maintainability:** The design must be modular. The database must be backed up to prevent data loss.
*   **Compliance:** The web interface must comply with W3C XHTML 1.0 Transitional standard.

**Constraints, Assumptions & Dependencies**
*   Must be developed in Ruby without using frameworks.
*   Must run on the Linux-based Wilma server.
*   Assumes users have a web browser supporting XHTML and an HTTP connection to the server.
*   Depends on the continuous availability of the Wilma server and its MySQL database.

**Priorities & Acceptance Approach**
Requirements are categorized as Critical (for first prototype), Sufficient (for final product), or Optional. Acceptance will be based on fulfilling the externally verifiable functional and non-functional requirements stated in the SRS.
