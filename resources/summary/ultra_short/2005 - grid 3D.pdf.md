**Purpose & Scope**
The system is a 3D visualization tool for biological data, allowing users to investigate and compare data attributes. It plots data points from a formatted input file and provides interactive manipulation of the 3D view. It does not generate or pre-process the raw biological data itself.

**Product Background / Positioning**
The product is developed for the parasitology department at NIMR to fill a gap where existing visualization tools are insufficient. It is intended for research merit and will be used alongside data generation tools like Matlab, deployed via a web server (e.g., Tomcat/Apache).

**Core Functional Overview**
*   Plot up to 2000 data points in a 3D grid from a user-supplied data file.
*   Colour points based on a cluster attribute from the data.
*   Display a data point's name on a single mouse click.
*   Display all details of a data point on a double mouse click.
*   Allow selection of multiple points to display multiple names.
*   Allow user to rotate, zoom, and move (re-orient) the 3D grid.
*   Correctly label grid axes based on the input data file.

**Key Users & Usage Scenarios**
Primary users are research scientists, students, and data-mining scientists investigating proteins. User roles are defined by their goal: Identifiers supply data to find points of interest; Investigators retrieve detailed point information; Demonstrators use the 3D view to present data. All users can manipulate the grid view.

**Major External Interfaces**
The application is a server-side executable accessed via a Java-enabled web browser. It requires a formatted tab-delimited text file as input. It must run on both Windows (98/2000/NT/XP) and Linux/Solaris operating systems.

**Key Non-functional Requirements**
*   The application must start within 30 seconds, dependent on the number of data points.
*   Interaction with data points (e.g., click response) must have a delay no longer than 2 seconds.
*   Must be usable with only a mouse and keyboard.
*   Must run on a mid-range personal computer.
*   The interface must use a black-on-white colour scheme for clear printed screenshots.

**Constraints, Assumptions & Dependencies**
*   Must be developed and ready for inclusion in a scientific paper by March 2005.
*   Execution is constrained to the server side.
*   Assumes users have basic computing skills: operating system use, Java browser, mouse/keyboard, file handling, and command line input.
*   Depends on user ability to create correctly formatted tab-delimited input files.

**Priorities & Acceptance Approach**
Core functionality (3D plotting, point selection, view manipulation) is critical for the March 2005 deadline. Cross-platform operation (Windows/Linux) is a fixed constraint. Acceptance will be based on correct visual rendering of test data files, adherence to performance timing, and full operation on the specified platforms.
