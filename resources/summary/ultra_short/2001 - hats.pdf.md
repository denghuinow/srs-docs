**Purpose & Scope**
The system is a platform-independent graphical user interface (GUI) for the High Assurance Transformation System (HATS). It enables users to interact with HATS to perform and examine formal, semantics-preserving program transformations. The GUI manages applications, orchestrates parsing and execution of transformation programs, and displays the resulting syntax trees and formatted text. It does not perform the core transformation logic itself; that is handled by the external HATS-SML service.

**Product Background / Positioning**
HATS is a tool for transformation-based software development, developed by the High Integrity Software program at Sandia National Laboratories. The existing prototype GUI lacks portability and adequate display capabilities. This new GUI aims to replace it, making HATS more user-friendly and accessible to the transformation and research community to increase adoption and provide feedback.

**Core Functional Overview**
1.  Create, open, save, and delete applications (collections of related domain and transformation files).
2.  Parse transformation language programs and target files into Syntax Derivation Trees (SDTs).
3.  Execute transformation language programs on target files via HATS-SML.
4.  Generate pretty-printed text output from SDTs.
5.  Graphically display, navigate, and manipulate SDTs (expand/collapse nodes, search).
6.  Display and search pretty-printed text output.
7.  Display error and standard output streams from HATS-SML.

**Key Users & Usage Scenarios**
The primary user is a domain expert with high computer literacy, understanding formal transformations and hierarchical file systems. There is only one user type with full system access. Typical scenarios include setting up a new transformation application, parsing files, running a transformation, and then inspecting the resulting SDT and formatted text output to verify correctness.

**Major External Interfaces**
1.  **User Interface:** A menu-driven GUI (File, Application, Configure, Run, View menus).
2.  **Software Interface:** Communicates with the suite of HATS-SML programs (e.g., MakeParser, ParseTarget, ApplyTransformations) via command-line invocation and stream capture.
3.  **Host OS Interface:** Uses OS services for file system operations (create, read, delete), process management (to launch HATS-SML and external editors), and time-stamp comparison.

**Key Non-functional Requirements**
1.  **Performance:** Must display an SDT with 10,000 nodes within 5 seconds. Scrolling a screen width of a 10,000-node SDT must take less than 3 seconds.
2.  **Portability:** Must run without code modification on Windows 2000, Sun Solaris 8, and Linux operating systems.
3.  **Implementation Constraint:** The system must be implemented in Java 1.3.
4.  **Algorithmic Complexity:** Text search, tree search, and scrolling algorithms must not exceed O(n²) complexity.

**Constraints, Assumptions & Dependencies**
1.  A Java Virtual Machine (JVM) must be installed on the host system.
2.  An ML interpreter and HATS-SML (version 2.0) must be installed and operational on the same system.
3.  The host OS must support a hierarchical file system.
4.  The system is constrained to be developed in Java and completed by December 2001.
5.  The GUI must manage applications where all related files are stored in a single directory.

**Priorities & Acceptance Approach**
Core functionality (application management, parsing, execution, and basic display) is highest priority. Advanced display manipulation (search, navigation window) is important but secondary. Acceptance will be based on the system correctly orchestrating HATS-SML operations per the defined protocol, meeting the performance metrics, and functioning on the three specified operating systems.
