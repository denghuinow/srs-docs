**Purpose & Scope**
The system processes and archives telemetry data from the ASPERA-3 instrument package on the Mars Express mission. It converts raw telemetry into standardized scientific data products (IDFS data sets) for the science team and public, and submits them to the NASA Planetary Data System for long-term archival. It does not include the design of the scientific processing algorithms for each instrument sensor.

**Product Background / Positioning**
This is the ground data system for the ASPERA-3 space plasma instrument on the ESA Mars Express spacecraft. It is positioned between the ESA mission operations center (ESOC), which provides the raw telemetry, and the international ASPERA-3 science team and the NASA Planetary Data System (PDS), which are the primary consumers of its processed outputs.

**Core Functional Overview**
*   Acquire ASPERA-3 and Mars Express orbit/attitude telemetry data from ESOC.
*   Process all ASPERA-3 science telemetry into IDFS data sets.
*   Generate and archive intermediate cleaned-up telemetry files if not provided by ESOC.
*   Store all raw telemetry and processed IDFS data sets on a local SwRI archive.
*   Provide password-protected, web-based displays of ASPERA-3 data for science team analysis.
*   Provide public web-based displays of the most current data.
*   Distribute IDFS data sets and any intermediate files to all ASPERA-3 Co-Investigators.
*   Submit validated, PDS-compliant ASPERA-3 IDFS data to the NASA Planetary Data System.

**Key Users & Usage Scenarios**
*   **ASPERA-3 Science Team (Co-Investigators):** Primary users. Access all processed data via password-protected web displays and receive distributed data sets for detailed scientific analysis.
*   **APAF Operators:** Run the daily automated processing pipeline, monitor system status, and handle any errors.
*   **General Public:** View pre-defined, non-sensitive displays of recent instrument data via the public website.
*   **NASA PDS:** Receives finalized, validated data sets for permanent archiving.

**Major External Interfaces**
*   **Input:** Telemetry data streams (ASPERA-3 and spacecraft Orbit/Attitude) delivered via the NISN network from ESOC.
*   **Output:** Distribution of IDFS data sets to Co-Investigators; submission of data sets to the NASA Planetary Data System (PDS).
*   **User Interface:** Web server (`www.aspera-3.org`) for both public and secured team access.

**Key Non-functional Requirements**
*   **Performance/Reliability:** Processed IDFS data must be delivered to Co-Investigators within 24 hours of error-free telemetry acquisition.
*   **Compliance/Archival:** All ASPERA-3 data must be submitted to the NASA PDS in a PDS-compliant form within 6 months of acquisition.
*   **Security/Privacy:** The web server must provide password protection for science team data and displays until the data is made public.
*   **Availability:** The system requires a continuous network connection between SwRI and the NISN for data transfer.

**Constraints, Assumptions & Dependencies**
*   **Dependency:** Telemetry data format is defined by external ESOC and instrument team (FMI/UMU) documents.
*   **Dependency:** Processing algorithms and IDFS data set definitions for each instrument sensor are defined in separate, external Software Design Documents (SDDs).
*   **Constraint:** The system must be developed on a schedule that supports the Mars Express launch (planned June 2003) and mission operations.
*   **Assumption:** The system operates on designated UNIX-based development and production computers at SwRI.

**Priorities & Acceptance Approach**
The highest priority is the reliable daily processing and distribution of data to the science team (24-hour delivery). The mandatory, contractually binding requirement is the validated delivery of data to the NASA PDS within the 6-month deadline. Acceptance will be verified through demonstration of the processing pipeline and analysis of output data products against simulated input telemetry.
