**Purpose & Scope**
The system is a digital repository to acquire, organize, preserve, and provide long-term access to NLM's digitized and born-digital biomedical collection materials. It is scoped to collection materials under Library Operations responsibility, excluding non-collection resources like the UMLS or Visible Human project. It does not include web harvesting functionality itself, though harvested data can be stored.

**Product Background / Positioning**
The repository is needed to manage and preserve existing and growing digital collections, fulfilling NLM's core mission. It will exist alongside and must interface with existing specialized repositories like PubMed Central (PMC). It will follow the Open Archival Information System (OAIS) reference model as its conceptual framework.

**Core Functional Overview**
1.  Ingest digital materials via multiple streams (e.g., e-journals, images, videos), including receiving, validating, and converting submissions.
2.  Generate and manage Archival Information Packages (AIPs) that include the digital object and its full metadata.
3.  Provide secure, reliable archival storage with media refreshment and disaster recovery capabilities.
4.  Manage descriptive, administrative, and structural metadata to support discovery, retrieval, and preservation.
5.  Administer the system, including negotiating submission agreements, configuration management, and auditing.
6.  Conduct preservation planning by monitoring technology and community needs to develop migration strategies.
7.  Provide controlled access to different user classes, with search and retrieval functionality, generating Dissemination Information Packages (DIPs).

**Key Users & Usage Scenarios**
*   **General Public & NIH Staff:** Search, view, and retrieve materials subject to access restrictions (e.g., embargo, location). NIH staff may have broader access rights.
*   **NLM Staff (Metadata Access):** Create, review, and edit object metadata without altering the files.
*   **NLM Staff (Object Maintenance):** Perform quality checks, format conversions, and file manipulations.
*   **NLM System Administrators:** Manage system configuration, assign user rights, and perform development.
Typical scenarios include ingesting a new journal issue, a researcher searching for historical images, and staff migrating a file format to prevent obsolescence.

**Major External Interfaces**
The system must interface with NLM's Integrated Library System (ILS) for bibliographic data. It must accept data via electronic transfer (e.g., FTP) and from physical media. It will provide access via web interfaces for end-users and staff, and must support metadata harvesting protocols like OAI-PMH.

**Key Non-functional Requirements**
*   **Security:** Must conform to HHS/NIH security standards and policies. Access must be controlled via multiple granular permission levels.
*   **Reliability & Availability:** Must provide disaster recovery capabilities and be compatible with the NIH off-site backup facility (NCCS). It is not a "dark archive"; objects must be available for access.
*   **Maintainability:** Must keep a complete audit trail of all actions performed on objects and within the system.
*   **Performance:** Must support the bulk ingest of materials as well as individual objects.
*   **Compatibility:** Must support multiple languages and non-Roman scripts for ingest, management, and access.

**Constraints, Assumptions & Dependencies**
*   **Constraints:** Must work within existing NLM security policies and interface with the current ILS. Must accommodate important materials in non-standard or obsolete formats as exceptions.
*   **Assumptions:** A distributed custodial model will be used; not all objects will be stored in the repository, but their metadata will be managed by NLM. The system will not provide special software for accessing materials (e.g., for audiovisuals).
*   **Dependencies:** Success depends on developing new policies for ingest, migration strategies, and metadata standards.

**Priorities & Acceptance Approach**
The highest priority is preserving the intellectual content of materials. The preservation of original "look and feel" is a secondary consideration. Acceptance will be based on the system's ability to fulfill the core OAIS functions (Ingest, Archival Storage, Data Management, Administration, Preservation Planning, Access) as defined, while meeting the security, audit, and access control requirements.
