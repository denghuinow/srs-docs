**Purpose & Scope**
The system is a prototype smart home management system for controlling environmental and security devices. It allows remote monitoring and control of temperature, humidity, security, and appliances via a web interface. It is a limited prototype for business evaluation and operates in a simulated environment, not a physical home.

**Product Background / Positioning**
This is a proof-of-concept prototype developed by the DigitalHomeOwner division to inform future commercial product decisions. It is based on a prior high-level requirements definition and is intended to be extendable into a commercial product.

**Core Functional Overview**
*   Remotely monitor and set temperatures for up to eight thermostats.
*   Remotely monitor and set humidity levels for up to eight humidistats.
*   Manage a security system with up to fifty contact sensors and activate light/sound alarms.
*   Remotely monitor and control the on/off state of up to one hundred appliances/lights.
*   Create and modify monthly plans for automatic device settings.
*   Generate monthly historical reports on environmental data and security events.

**Key Users & Usage Scenarios**
*   **General User:** Monitors and controls home devices via a web interface. Familiar with basic web navigation.
*   **Master User:** Has General User rights plus the ability to change system configuration (e.g., add accounts, change defaults).
*   **DH Technician:** Sets up and maintains the system configuration, with rights to start/stop the system and establish user accounts. Trained on the system.

**Major External Interfaces**
*   User interacts via a web interface from a computer, cell phone, or PDA.
*   The system core is a home web server.
*   A gateway device connects the server to home devices via wireless communication.
*   Interfaces with simulated sensors and controllers (thermostats, humidistats, contact sensors, power switches).

**Key Non-functional Requirements**
*   Display updates for environmental conditions at least every two seconds.
*   Sensor data acquisition rate minimum of 10 Hz.
*   Wireless communication range of up to 1000 feet indoors.
*   Mean time between failures no less than 10,000 hours.
*   Daily backup of all system data and recovery from the most recent backup upon failure.
*   User authentication via account name and password with data encryption.

**Constraints, Assumptions & Dependencies**
*   This is a prototype to be completed within twelve months by a team of five.
*   The system will be tested in a realistic simulated environment only.
*   Development must use object-oriented methods (UML) and adhere to specified IEEE and company standards.
*   System cost for elements must be minimized.
*   Requires a broadband Internet connection (e.g., cable modem, DSL).

**Priorities & Acceptance Approach**
The primary goal is a functional prototype to enable business decisions. Acceptance will be based on demonstrating core monitoring/control functions for all device types in the simulated environment, meeting the defined reliability metric, and adhering to the development constraints and standards.
