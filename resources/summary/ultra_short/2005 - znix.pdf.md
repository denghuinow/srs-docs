**Purpose & Scope**
The system is an object-based, application-independent framework for managing and retrieving user information. It centralizes information from various sources into a hierarchical model defined by the user. It does not provide multi-user or networked operation at this stage.

**Product Background / Positioning**
ZNIX is a research project to refine traditional information management, positioning itself as a deeply OS-integrated alternative to systems like Project Haystack. It is designed to run on lower-resource hardware than contemporary systems like Windows Longhorn.

**Core Functional Overview**
*   Provide a centralized store for user information from specified applications (email, documents, contacts, web).
*   Allow users to build and view a customizable, hierarchical model of their information.
*   Automate data capture and categorization from integrated applications.
*   Archive information to removable media while maintaining its reference in the hierarchy.
*   Expose core functionality (entity/relationship management, queries) via a public API for client applications.
*   Provide a proxy mechanism to allow non-aware applications to interact with the framework.

**Key Users & Usage Scenarios**
Primary users are home users, managers, executives, and researchers with basic IT skills. They use the system to centrally manage personal and work information (emails, contacts, research documents) by creating semantic relationships between items, which they can later browse and retrieve.

**Major External Interfaces**
The system must interface with specified third-party applications (e.g., Outlook, Internet Explorer, Word) to capture information. It provides a user interface similar to Windows Explorer for browsing. It exposes a software API for ZNIX-aware client development.

**Key Non-functional Requirements**
*   Must run on a Pentium III 1-GHz PC with 256 MB RAM.
*   Framework shell memory usage shall not exceed 40 MB.
*   Mean Time Between Failures (MTBF) shall exceed 3 months.
*   Must guard against malicious remote scripts and unintended user corruption of information.
*   Operates in single-user mode only.

**Constraints, Assumptions & Dependencies**
*   Constrained to run on Windows 2000 Professional and Windows XP.
*   Assumes compatibility with listed third-party application versions and their subsequent releases.
*   Assumes the security of the integrated third-party applications.
*   Licensed under LGPL (framework) and GPL (tools).

**Priorities & Acceptance Approach**
Core priority is providing the centralized store and user-defined hierarchical management. Acceptance is based on functional capability with the listed applications, adherence to specified performance/resource limits, and compliance with the stated licensing and standards (Windows Logo, Unicode).
