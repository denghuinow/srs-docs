## 1. Introduction

### 1.1 Purpose
This Software Requirements Specification (SRS) document defines the functional and non-functional requirements for the Tarrant County Indigent Justice Information System (IJIS). The primary purpose of this system is to automate and manage the end-to-end process for providing court-appointed legal counsel to indigent defendants in Tarrant County, Texas, ensuring compliance with the Texas Fair Defense Act and related statutes.

### 1.2 Document Conventions
*   **Bold text** is used for key terms and entity names.
*   `Monospaced text` is used for system messages, field names, or code references.
*   Requirements are uniquely identified as **FR** (Functional Requirement) or **NFR** (Non-Functional Requirement).

### 1.3 Project Scope
The IJIS will be a centralized, web-based platform that streamlines the submission, processing, tracking, and administration of indigent defense services. The system's scope encompasses the following core areas:
*   Electronic submission and processing of **Requests for Appointed Counsel**.
*   Management of qualified **Defense Attorney** lists and automated appointment rotation.
*   Tracking of **Defendant** contact and case milestones.
*   Management of case filing notifications from the **District Attorney**.
*   Processing of **Attorney Compensation** requests from submission through judicial approval to payment.
*   Generation of comprehensive compliance reports for the **Task Force on Indigent Defense (TFID)**.
*   Secure integration with external justice systems (Court Case Management, District Attorney filing system, County financial system).

**Out of Scope:**
*   The system will not replace the external Court Case Management System.
*   The system will not perform automated legal analysis or provide legal advice.
*   The system will not manage the county's general financial operations outside of attorney payment requests related to indigent defense.

### 1.4 References
*   Texas Fair Defense Act
*   Texas Code of Criminal Procedure (CCP), Articles 1.051, 15.17, 26.04, 26.05
*   Texas Government Code, Chapter 79 (Task Force on Indigent Defense)
*   Texas Uniform Electronic Transactions Act (UETA)

### 2.2 User Classes and Characteristics
| User Class | Description | Key Characteristics |
| :--- | :--- | :--- |
| **Magistrate** | Judicial officer conducting arrestee hearings. | Mobile/remote access needed; requires simple, fast interface for submission. |
| **OAA Staff** | Office of Attorney Appointments administrator. | Primary system user; requires comprehensive workflow management tools. |
| **Defense Attorney** | Appointed counsel for indigent defendants. | External user; needs secure portal for notifications, contact logging, and payment submission. |
| **Judge** | County or District Court Judge. | Reviews and approves payment requests; manages attorney qualification lists. |
| **Court Coordinator** | Manages court dockets and settings. | Inputs setting data into external system; may trigger notifications in IJIS. |
| **District Attorney Staff** | Represents the State in criminal proceedings. | Provides filing decisions; requires secure, standardized notification method to IJIS. |
| **Auditor Staff** | County financial officer. | Receives approved payment data for processing in county financial system (SAP). |
| **TFID Analyst** | State compliance monitor. | External recipient of generated reports; read-only access to aggregated data. |
| **System Administrator** | Manages IJIS configuration and users. | Technical role; configures rotation lists, user accounts, and system parameters. |

### 2.3 Operating Environment
*   **Software:** Web-based application accessible via standard browsers (Chrome, Edge, Firefox). Must be compatible with existing County network and security infrastructure.
*   **Hardware:** Hosted on County servers or approved cloud infrastructure meeting Texas CJIS and data security standards.
*   **Integrations:** Must operate in an environment with the following external systems:
    *   Court Case Management System (CCMS)
    *   District Attorney's Electronic Case Filing System (ECFS)
    *   County Financial System (SAP)

### 2.4 Design and Implementation Constraints
1.  **Legal Compliance:** Design must strictly adhere to timelines and procedures mandated by the Texas Fair Defense Act and CCP.
2.  **Integration:** System design is constrained by the APIs and data formats provided by the legacy external systems (CCMS, ECFS, SAP).
3.  **Security:** Must comply with Texas Department of Information Resources (DIR) security standards and any County-specific IT policies.

### 2.5 Assumptions and Dependencies
*   **Assumption:** External systems (CCMS, ECFS) will provide stable, documented interfaces for integration.
*   **Assumption:** Necessary legal authority for electronic signatures and records under UETA will be secured.
*   **Dependency:** Project timelines are dependent on approval from the Tarrant County Commissioners Court.
*   **Dependency:** Final requirements for TFID reporting are dependent on state guidelines, which may evolve.

## 3. System Features and Requirements

### 3.1 Feature: Manage Request for Appointed Counsel
**Description:** This feature allows Magistrates to electronically submit requests and enables the OAA to process them, determining indigency and appointing counsel.

**3.1.1 Functional Requirements**
*   **FR-1.1:** The system shall provide a secure web form for a **Magistrate** to electronically submit a **Request for Appointed Counsel**, capturing at minimum: Defendant ID, charges, financial affidavit status, and indigency determination.
*   **FR-1.2:** The system shall timestamp the submission of each request and assign a unique **Request ID**.
*   **FR-1.3:** Upon receipt, the system shall automatically validate the request against existing **Appointment** records to prevent duplicate appointments for the same defendant and case.
*   **FR-1.4:** The system shall present a validated request to an **OAA Staff** user in a "For Processing" work queue.
*   **FR-1.5:** The system shall allow OAA Staff to select the next eligible attorney from the appropriate qualification-level **Rotation List** based on the offense type.
*   **FR-1.6:** The system shall automatically generate an **Appointment** record, linking the **Defendant**, **Attorney**, and **Case/Charge**, and record the **Appointment Date**.
*   **FR-1.7:** The system shall immediately notify the appointed **Defense Attorney** (via email and/or portal alert) of the new appointment.
*   **FR-1.8:** The system shall escalate alerts to OAA supervisors if a request remains unprocessed for more than 20 hours (supporting the one-working-day mandate).

### 3.2 Feature: Manage Defendant Contact and Case Lifecycle
**Description:** This feature tracks mandatory attorney-defendant contact, receives case filing decisions, and manages court setting notifications.

**3.2.1 Functional Requirements**
*   **FR-2.1:** The system shall provide a portal for a **Defense Attorney** to log the date and method of first contact with a defendant.
*   **FR-2.2:** The system shall receive an electronic notification from the **District Attorney's ECFS** regarding the filing decision (charges Accepted, Rejected, or Modified).
*   **FR-2.3:** Upon receiving a filing decision, the system shall update the relevant **Case/Charge** record and automatically notify the appointed **Defense Attorney**.
*   **FR-2.4:** The system shall receive court setting information (date, time, type, outcome) from the **Court Case Management System** via integration.
*   **FR-2.5:** The system shall automatically generate notifications to the **Defense Attorney** and relevant parties for upcoming court settings based on integrated data.

### 3.3 Feature: Manage Attorney Compensation
**Description:** This feature facilitates the submission, judicial review, approval, and financial processing of attorney payment requests.

**3.3.1 Functional Requirements**
*   **FR-3.1:** The system shall provide a form for a **Defense Attorney** to submit an itemized **Payment Request**, including services performed, hours billed, and a calculated total amount.
*   **FR-3.2:** The system shall route the submitted **Payment Request** to the appropriate **Judge** for review and approval based on the case assignment.
*   **FR-3.3:** The system shall allow a **Judge** to view, modify, approve, or reject a **Payment Request**, with all changes audited.
*   **FR-3.4:** Upon judicial approval, the system shall export the approved payment data in a format compatible with the County **Auditor's** financial system (SAP) for final processing.
*   **FR-3.5:** The system shall provide the **Defense Attorney** with status updates on their payment requests (e.g., Submitted, Under Review, Approved, Paid).

### 3.4 Feature: Manage Attorney Lists and System Administration
**Description:** This feature allows for the management of attorney rosters, rotation lists, and basic system configuration.

**3.4.1 Functional Requirements**
*   **FR-4.1:** The system shall allow **Judges** or **OAA Administrators** to add, suspend, or reactivate attorneys on qualification lists, specifying their approved offense levels.
*   **FR-4.2:** The system shall maintain separate, automated **Rotation Lists** for each attorney qualification level (e.g., misdemeanor, felony, capital).
*   **FR-4.3:** The system shall record the date and reason for any change to an attorney's **List Status**.
*   **FR-4.4:** The system shall provide a configuration interface for **System Administrators** to define user roles, access permissions, and system parameters (e.g., notification templates, escalation timeframes).

### 3.5 Feature: Reporting and Compliance
**Description:** This feature generates standard and ad-hoc reports for operational management and state-mandated compliance.

**3.5.1 Functional Requirements**
*   **FR-5.1:** The system shall generate the comprehensive annual and quarterly reports required by the **Task Force on Indigent Defense (TFID)** as per Texas Government Code, Chapter 79.
*   **FR-5.2:** The system shall provide configurable report parameters (date ranges, court type, attorney, disposition status, etc.).
*   **FR-5.3:** Reports shall be exportable in standard formats (PDF, Excel, CSV).
*   **FR-5.4:** The system shall provide operational dashboards for OAA management showing key metrics (e.g., requests pending, average processing time, appointment rates).

## 4. External Interface Requirements

### 4.1 User Interfaces
*   The system shall provide a responsive, web-based interface compatible with modern browsers.
*   Interfaces shall be role-based, presenting only relevant functions and data to each user class.
*   A public-facing, secure portal shall be provided for Defense Attorneys to receive notifications and submit information.

### 4.2 Hardware Interfaces
*   Must support access from County-issued laptops, desktops, and mobile devices.
*   Must interface with County printers for generating physical documents if required.

### 4.3 Software Interfaces
1.  **Court Case Management System (CCMS):** IJIS shall consume a real-time or daily batch feed of case setting data (hearing dates, types, outcomes) and defendant/case identifiers.
2.  **District Attorney ECFS:** IJIS shall receive an automated notification (e.g., via web service or secure file transfer) when a filing decision is entered for a case involving an appointed attorney.
3.  **County Financial System (SAP):** IJIS shall export a batch file of judicially approved **Payment Requests** in the predefined format required by the Auditor's office for payment processing.

### 4.4 Communications Interfaces
*   All external system integrations shall use secure communication protocols (HTTPS, SFTP).
*   The system shall send email notifications (SMTP) using the County's email server.
*   Portal alerts will be implemented within the application interface.

## 5. Non-Functional Requirements

### 5.1 Performance Requirements
*   **NFR-1 (Timeliness):** The system shall support the processing of a **Request for Appointed Counsel** from submission to attorney assignment within one (1) working day, as mandated by law. System workflows and alerts shall be configured to enforce this.
*   **NFR-2:** All common user interactions (page loads, form submissions) shall complete in less than 3 seconds under normal load (100 concurrent users).
*   **NFR-3:** The system shall be available 99.5% of the time during standard business hours (7:00 AM - 7:00 PM CT), excluding scheduled maintenance.

### 5.2 Safety and Security Requirements
*   **NFR-4:** The system shall implement role-based access control (RBAC), ensuring users can only access functions and data pertinent to their role.
*   **NFR-5:** All sensitive data (personally identifiable information, financial data) shall be encrypted at rest and in transit.
*   **NFR-6:** The system shall maintain a comprehensive audit log recording user ID, timestamp, action performed, and entity changed for all create, update, and delete operations.
*   **NFR-7:** The system shall comply with Texas UETA requirements for electronic signatures and record retention for legal documents like indigency affidavits.

### 5.3 Software Quality Attributes
*   **NFR-8 (Reliability):** The system shall have a mean time between failures (MTBF) of no less than 720 hours.
*   **NFR-9 (Usability):** New users shall be able to complete core tasks (e.g., submit a request, log contact) with less than 30 minutes of training, as measured by user acceptance testing.
*   **NFR-10 (Maintainability):** The system shall be designed with modular components to allow for updates to individual features (e.g., reporting, payment rules) with minimal impact on other system functions.

## 7. Appendices

### 7.1 Glossary
*   **Indigent:** A defendant who is financially unable to employ counsel.
*   **Rotation List:** A list of qualified attorneys, maintained in a specific order, used to appoint counsel sequentially to ensure fair distribution of cases.
*   **TFID:** The Texas Task Force on Indigent Defense, the state body responsible for oversight and standards.
*   **OAA:** The Office of Attorney Appointments for Tarrant County.
