## 1. Introduction

### 1.1 Purpose
This document defines the functional and non-functional requirements for the High Assurance Transformation System (HATS) Graphical User Interface (GUI). The purpose of this GUI is to provide a platform-independent, user-friendly interface that enables domain experts to orchestrate formal program transformations, visualize syntax trees, and inspect results, thereby increasing the accessibility and adoption of the HATS tool within the research community.

### 1.2 Scope
The HATS GUI is a front-end application that manages transformation "applications," orchestrates calls to the external HATS-SML service (which performs the core transformation logic), and displays the resulting Syntax Derivation Trees (SDTs) and formatted text. The system includes functionality for file management, parsing, transformation execution, and graphical visualization. It explicitly excludes the implementation of the transformation logic itself, which remains the responsibility of the HATS-SML backend.

### 1.3 Definitions, Acronyms, and Abbreviations
*   **HATS:** High Assurance Transformation System.
*   **HATS-SML:** The core transformation engine, implemented in Standard ML.
*   **GUI:** Graphical User Interface.
*   **SDT:** Syntax Derivation Tree. The abstract syntax tree representation of parsed code.
*   **SML:** Standard Meta-Language.
*   **JVM:** Java Virtual Machine.
*   **OS:** Operating System.

## 2. Overall Description

### 2.1 Product Perspective
The HATS GUI is a new, self-contained component designed to replace an existing non-portable prototype. It acts as a mediator between the user and the HATS-SML service suite. The system architecture is depicted below:

```
[ User ] <--> [ HATS GUI (Java) ] <--> [ HATS-SML Service (SML) ]
                  |        |                         |
                  |        |                  [ Target / Transform Files ]
                  |        |
           [ Host OS File System ]        [ ML Interpreter ]
```

### 2.2 Product Functions
The core functions of the HATS GUI are:
1.  **Application Management:** Create, open, save, and delete "applications," which are directories containing related domain and transformation files.
2.  **Orchestration:** Parse transformation programs and target files into SDTs by invoking HATS-SML tools (`MakeParser`, `ParseTarget`).
3.  **Transformation Execution:** Execute transformation programs on target files by invoking the HATS-SML tool (`ApplyTransformations`).
4.  **Output Generation:** Generate pretty-printed text output from SDTs.
5.  **Visualization:** Graphically display, navigate, and manipulate SDTs.
6.  **Text Display & Search:** Display and search within pretty-printed text output.
7.  **Log Display:** Capture and display standard output and error streams from HATS-SML processes.

### 2.3 User Characteristics
The sole intended user is a **Domain Expert** with the following attributes:
*   **High computer literacy.**
*   **Expert understanding** of formal, semantics-preserving program transformations.
*   **Familiarity** with hierarchical file systems and command-line tools.
*   **Goal:** To efficiently set up, run, and verify complex program transformations.

### 2.4 Constraints
1.  **Implementation Language:** The system must be implemented in Java 1.3.
2.  **Dependencies:** Requires a JVM, an ML interpreter, and HATS-SML version 2.0 to be pre-installed and operational on the host machine.
3.  **File Management:** An "application" must be contained entirely within a single directory.
4.  **Schedule:** Must be completed by December 2001.
5.  **Host OS:** The host operating system must support a hierarchical file system.

### 2.5 Assumptions and Dependencies
*   The HATS-SML service command-line interface and behavior are stable and as documented.
*   The host OS provides standard services for file I/O, process creation, and stream handling.
*   The user has appropriate permissions to read, write, and execute files in the application directory.

## 3. Specific Requirements

### 3.1 External Interface Requirements

#### 3.1.1 User Interfaces
The GUI shall present a main window with a menu bar containing the following top-level menus:
*   **File:** Operations for the GUI session (e.g., Exit).
*   **Application:** Create, Open, Save, Delete application.
*   **Configure:** Set paths to HATS-SML tools and external text editor.
*   **Run:** Parse Target, Parse Transform, Run Transformation.
*   **View:** Control visibility of panels (SDT Viewer, Text Output Panel, Log Panel).

Primary display areas shall include:
1.  A **Tree View Panel** for interactive SDT display.
2.  A **Text Output Panel** for displaying pretty-printed code.
3.  A **Log/Console Panel** for HATS-SML standard/error output.

#### 3.1.2 Software Interfaces
The GUI shall interact with the following external software components via command-line invocation:
*   `MakeParser`: To generate a parser for a domain.
*   `ParseTarget`: To parse a target file into an SDT.
*   `ApplyTransformations`: To apply a transformation program to a target SDT.
*   `[External Text Editor]`: To open files for direct editing, configurable by the user.

The GUI shall capture and parse the `stdout` and `stderr` streams from these processes.

#### 3.1.3 Communications Interfaces
Not applicable. All communication is via local process invocation and file I/O.

### 3.2 Functional Requirements

#### 3.2.1 Application Management (FR-AM)
*   **FR-AM-1:** The system shall allow the user to create a new application, which creates a new directory on the filesystem.
*   **FR-AM-2:** The system shall allow the user to open an existing application directory.
*   **FR-AM-3:** The system shall allow the user to save the current application state (e.g., open file references, window layout).
*   **FR-AM-4:** The system shall allow the user to delete an existing application directory (with user confirmation).

#### 3.2.2 Parsing Orchestration (FR-PO)
*   **FR-PO-1:** The system shall invoke `MakeParser` on a user-specified domain file when requested.
*   **FR-PO-2:** The system shall invoke `ParseTarget` on a user-selected target file within the current application.
*   **FR-PO-3:** The system shall load the resulting SDT from the file generated by HATS-SML and prepare it for display.

#### 3.2.3 Transformation Execution (FR-TE)
*   **FR-TE-1:** The system shall invoke `ApplyTransformations` with a user-selected transformation program and target SDT.
*   **FR-TE-2:** The system shall load the resulting output SDT generated by the transformation.

#### 3.2.4 SDT Display and Manipulation (FR-SDT)
*   **FR-SDT-1:** The system shall graphically display an SDT in a scrollable, hierarchical tree view.
*   **FR-SDT-2:** The user shall be able to expand or collapse individual nodes in the tree.
*   **FR-SDT-3:** The user shall be able to search for text within node labels. The search algorithm shall have a worst-case complexity no greater than O(n²).
*   **FR-SDT-4:** The system shall provide a navigation aid (e.g., a minimap or breadcrumb trail) for large trees.

#### 3.2.5 Text Output Handling (FR-TO)
*   **FR-TO-1:** The system shall generate and display pretty-printed text from any loaded SDT.
*   **FR-TO-2:** The user shall be able to search for text within the pretty-printed output. The search algorithm shall have a worst-case complexity no greater than O(n²).

#### 3.2.6 Log and Output Display (FR-LOG)
*   **FR-LOG-1:** The system shall display all standard output from invoked HATS-SML processes in a dedicated panel.
*   **FR-LOG-2:** The system shall display all error output from invoked HATS-SML processes in a dedicated panel, with clear visual distinction from standard output.

### 3.3 Non-Functional Requirements

#### 3.3.1 Performance Requirements
*   **PERF-1:** The system shall display an SDT containing 10,000 nodes within 5 seconds of the SDT being loaded and ready for rendering.
*   **PERF-2:** Horizontal or vertical scrolling across a screen width of a fully rendered 10,000-node SDT shall have a latency of less than 3 seconds.
*   **PERF-3:** Tree search and text search operations shall execute with algorithmic complexity not exceeding O(n²).

#### 3.3.2 Portability Requirements
*   **PORT-1:** The system shall run without any source code modification on the following operating systems:
    *   Microsoft Windows 2000
    *   Sun Solaris 8
    *   Linux (kernel 2.2 or later)
*   **PORT-2:** The system shall rely only on standard Java 1.3 APIs and shall not use OS-specific native calls.

#### 3.3.3 Implementation Constraints
*   **IMPL-1:** The system shall be developed in Java, version 1.3.
*   **IMPL-2:** The GUI shall use the standard Java Swing (JFC) toolkit for its interface components.

## 4. Appendices

### 4.1 Priority and Acceptance
*   **Priority 1 (Core):** Application Management (FR-AM), Parsing Orchestration (FR-PO), Transformation Execution (FR-TE), Basic SDT Display (FR-SDT-1, FR-SDT-2), and Log Display (FR-LOG). These are mandatory for acceptance.
*   **Priority 2 (Important):** SDT Search & Navigation (FR-SDT-3, FR-SDT-4), Text Output Search (FR-TO-2). These are required for a complete product but may be delivered in a subsequent update if necessary to meet schedule constraints.

**Acceptance Criteria:** The system will be deemed acceptable when it successfully fulfills all Priority 1 requirements, meets the stated Performance and Portability requirements, and correctly orchestrates the HATS-SML service according to its defined protocol on all three target operating systems.
