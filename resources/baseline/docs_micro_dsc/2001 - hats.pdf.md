# Software Requirements Specification (SRS)
## High Assurance Transformation System (HATS) - Graphical User Interface (GUI)

**Document Version:** 1.0  
**Date:** October 26, 2023  
**Status:** Draft for Review

---

### 1. Introduction

#### 1.1 Purpose
This document defines the requirements for the High Assurance Transformation System Graphical User Interface (HATS-GUI). The purpose of this software is to provide a platform-independent, user-friendly interface for managing transformation applications, orchestrating the execution of transformation programs, and visualizing their outputs. This SRS is intended for use by the project stakeholders, developers, testers, and project managers.

#### 1.2 Scope
The HATS-GUI will be a standalone Java application that serves as the primary user interface for the HATS ecosystem. It will allow users to interact with the core HATS-SML (version 2.0) service programs without using command-line tools. The GUI will manage the lifecycle of transformation "applications," execute transformations on target files, and present the results (Syntax Derivation Trees and pretty-printed text) in an intuitive, navigable format. The system will not modify the underlying HATS-SML transformation engine logic; it will act as a controller and visualizer.

#### 1.3 Definitions, Acronyms, and Abbreviations
*   **HATS:** High Assurance Transformation System.
*   **HATS-SML:** HATS Specification and Transformation Language – the core engine service program (v2.0).
*   **GUI:** Graphical User Interface.
*   **SDT:** Syntax Derivation Tree – a tree representation of the syntactic structure of source code after parsing.
*   **Platform-Independent:** The ability to run identically on Windows 2000, Sun Solaris, and Linux operating systems.
*   **Application:** In HATS-GUI context, a collection of related files (transformation programs, target files, configuration) residing in a single directory.

#### 1.4 References
*   HATS-SML Version 2.0 Service Program Interface Documentation.
*   Java Platform Standard Edition (J2SE) Specification for target platforms.

#### 1.5 Overview
The remainder of this document is structured as follows: Section 2 provides an overall description of the product, its functions, and constraints. Section 3 details the specific requirements for the system, including functional, external interface, and non-functional requirements.

### 2. Overall Description

#### 2.1 Product Perspective
The HATS-GUI is a new component that integrates with the existing HATS ecosystem. It is a dependent system that interfaces with the HATS-SML service programs as a client.

**System Interfaces:**
*   **HATS-SML Service Programs:** The GUI will invoke command-line executables of HATS-SML, passing appropriate arguments and managing input/output files as per the SML interface specification.

**User Interfaces:** The primary interface will be a graphical window-based application built with Java Swing or AWT to ensure platform independence. It will include menus, toolbars, dialog boxes, tree viewers, and text display panels.

**Hardware Interfaces:** None specified beyond the requirements of the Java Runtime Environment (JRE) on the supported operating systems.

**Software Interfaces:** Requires a compatible JRE (version to be determined) installed on the host system. Must be able to execute system processes (the HATS-SML binaries).

**Communications Interfaces:** None. All communication is local via file system and process execution.

#### 2.2 Product Functions
1.  **Application Management:** Create, select, open, and configure distinct HATS transformation projects ("applications").
2.  **Transformation Orchestration:** Initiate, monitor, and control the parsing and execution of transformation language programs on user-selected target files by calling HATS-SML services.
3.  **Output Visualization:** Display the results of transformations, specifically:
    *   Navigable, graphical Syntax Derivation Trees (SDTs).
    *   Pretty-printed textual output of transformed code.
4.  **File System Abstraction:** Enforce and manage the constraint that all files for one application reside in a single directory.

#### 2.3 User Characteristics
The intended users are software engineers and transformation specialists familiar with the concepts of program transformation and the HATS-SML language. They are technically proficient but require an efficient interface to manage multiple transformation tasks and inspect complex results.

#### 2.4 Constraints
1.  **Implementation Language:** The application must be implemented in Java.
2.  **Platform Independence:** Must be fully functional on Windows 2000, Sun Solaris, and Linux without modification.
3.  **External Dependency:** Must interface exclusively with the existing HATS-SML version 2.0 service programs. The GUI cannot alter these services.
4.  **Application Directory Structure:** All files (source, target, configuration, output) belonging to a single logical application must be contained within one directory. The GUI must enforce and utilize this structure.

#### 2.5 Assumptions and Dependencies
*   The HATS-SML version 2.0 executables are correctly installed and accessible on the system path or a configurable location known to the GUI.
*   The user has a basic understanding of HATS transformation concepts.
*   The Java Runtime Environment is available on the target platform.

### 3. Specific Requirements

#### 3.1 External Interface Requirements

##### 3.1.1 User Interfaces
*   **UI-FR-1: Main Application Window.** A resizable main window with a menu bar, a toolbar for common actions, a project/application navigation pane, and a main work area.
*   **UI-FR-2: Application Management Dialog.** A dialog to create a new application (specifying a directory) or select an existing application directory.
*   **UI-FR-3: Configuration Panel.** A panel or dialog to view and set application-specific configuration parameters required by HATS-SML.
*   **UI-FR-4: SDT Viewer Panel.** A dedicated panel capable of displaying a hierarchical, collapsible/expandable tree structure representing the Syntax Derivation Tree. Nodes must be selectable to reveal details.
*   **UI-FR-5: Text Viewer Panel.** A panel with text display capabilities (e.g., in a `JTextArea` or similar) for showing pretty-printed transformation output, with basic navigation and text wrapping.

##### 3.1.2 Hardware Interfaces
*   **HI-FR-1:** The software shall not require any specific hardware beyond standard keyboard, mouse, and display support provided by the JRE.

##### 3.1.3 Software Interfaces
*   **SI-FR-1:** The system shall spawn external processes to execute the `hats-sml-parser` and `hats-sml-executor` binaries (or equivalent names as per HATS-SML v2.0).
*   **SI-FR-2:** The system shall capture standard output and standard error streams from the HATS-SML processes and display them in a dedicated log/console area within the GUI.

##### 3.1.4 Communications Interfaces
*   **CI-FR-1:** None required.

#### 3.2 Functional Requirements

##### 3.2.1 Application Management
*   **FUN-AM-1:** The system shall allow the user to create a new HATS application.
    *   **FUN-AM-1.1:** Creation shall involve specifying a new or existing empty directory.
    *   **FUN-AM-1.2:** The system shall create necessary subdirectories (e.g., `src/`, `target/`, `config/`) within the application directory.
*   **FUN-AM-2:** The system shall allow the user to open an existing HATS application by selecting its root directory.
*   **FUN-AM-3:** The system shall enforce that all operations (file addition, transformation execution) for an open application are confined to files within its root directory tree.
*   **FUN-AM-4:** The system shall provide a visual representation of the application's file structure within the navigation pane.

##### 3.2.2 Transformation Orchestration
*   **FUN-TO-1:** The user shall be able to select a transformation program (SML file) from the current application's directory.
*   **FUN-TO-2:** The user shall be able to select one or more target files (source code files) from the current application's directory for transformation.
*   **FUN-TO-3:** The user shall be able to initiate the transformation process via a menu item, toolbar button, or context menu action.
*   **FUN-TO-4:** Upon initiation, the system shall:
    *   **FUN-TO-4.1:** Construct the appropriate command-line arguments for the HATS-SML parser and executor.
    *   **FUN-TO-4.2:** Execute the HATS-SML processes in the correct sequence.
    *   **FUN-TO-4.3:** Display process status and progress to the user.
    *   **FUN-TO-4.4:** Handle execution errors (e.g., missing files, SML errors) and present meaningful error messages to the user.
*   **FUN-TO-5:** The system shall save output files (SDT and pretty-printed text) to a specified location within the application's directory structure.

##### 3.2.3 Output Visualization
*   **FUN-OV-1:** The system shall automatically load and display the generated SDT file in the SDT Viewer Panel after a successful transformation.
    *   **FUN-OV-1.1:** The tree shall allow expand/collapse of nodes.
    *   **FUN-OV-1.2:** Selecting a tree node shall display relevant attributes (e.g., node type, source position) in a properties pane.
*   **FUN-OV-2:** The system shall automatically load and display the generated pretty-printed text file in the Text Viewer Panel after a successful transformation.
*   **FUN-OV-3:** The user shall be able to navigate between the SDT view and the text view, with potential for synchronized highlighting (e.g., selecting a tree node highlights the corresponding text region).

#### 3.3 Non-Functional Requirements

##### 3.3.1 Performance Requirements
*   **PER-1:** The GUI shall remain responsive (no freezing of the UI thread) during the execution of HATS-SML processes, which may be long-running.
*   **PER-2:** Loading and rendering of a typical SDT shall complete within 5 seconds on specified minimum hardware.

##### 3.3.2 Safety Requirements
*   **SAF-1:** The GUI shall not modify or delete any user file without explicit user confirmation, except for writing output to user-designated output directories.

##### 3.3.3 Security Requirements
*   **SEC-1:** The application does not handle network communication or sensitive authentication data. Security is limited to the host file system permissions enforced by the underlying OS.

##### 3.3.4 Software Quality Attributes
*   **QUAL-1: Maintainability:** The code shall be well-structured and commented to allow for future modifications.
*   **QUAL-2: Usability:** The interface shall be intuitive for a user familiar with HATS concepts. Common tasks should be achievable in 3 or fewer clicks.
*   **QUAL-3: Portability:** The application shall achieve 100% functional parity across Windows 2000, Sun Solaris, and Linux platforms. Platform-specific code paths are prohibited unless absolutely necessary and isolated.

##### 3.3.5 Design Constraints
*   **CON-1:** The system shall be developed using core Java libraries (J2SE) to ensure platform independence. The use of native code or platform-dependent libraries is forbidden.
*   **CON-2:** The system shall adhere to the application-directory constraint as specified in Section 2.4.
