### 1. Introduction

#### 1.1 Purpose
This document defines the functional and non-functional requirements for the Grid 3D Application. It is intended for use by the development team, stakeholders, and project supervisors to ensure a common understanding of the system's capabilities, constraints, and objectives. This SRS will serve as the foundation for design, implementation, testing, and project validation.

#### 1.2 Document Conventions
*   **Requirements:** Functional requirements are labeled `FR-XXX`. Non-functional requirements are labeled `NFR-XXX`.
*   **Priority:** (H) High, (M) Medium, (L) Low.
*   **Keywords:** `MUST`, `SHALL`, `WILL` indicate mandatory requirements. `SHOULD`, `COULD`, `MAY` indicate desirable but not mandatory features.

#### 1.3 Project Scope
The Grid 3D Application is a client-server visualization tool designed to render biological data points within an interactive, scientifically accurate three-dimensional grid. Its primary function is to enable researchers to load pre-processed data, visualize it in 3D with cluster-based color-coding, and interact with the visualization through rotation, zoom, selection, and information retrieval. Data generation, complex statistical analysis, collaboration, and mobile support are explicitly out of scope.

### 2. Overall Description

#### 2.1 Product Perspective
This is a new, standalone application. It will operate in a client-server model where the computational backend executes on a server, and the 3D visualization is rendered within a Java-enabled client (e.g., a web browser using Java Web Start or an applet). It interfaces with users via a graphical user interface and with data via formatted text files.

#### 2.2 Product Functions (Summary)
1.  Load and parse tab-delimited data files with a specific column structure.
2.  Plot data points in a 3D Cartesian coordinate system with labeled axes (X, Y, Z).
3.  Apply user-selected color schemes to data points based on cluster affiliation.
4.  Provide interactive 3D view manipulation: rotation, zoom (in/out), and pan.
5.  Enable selection of individual data points via mouse click to display detailed information.
6.  Enable selection of multiple data points for side-by-side comparison.
7.  Maintain performance with datasets of up to 2000 points.

### 3. System Features and Requirements

#### 3.1 Feature 1: Data Input and Management
**Description:** The system shall accept, validate, and parse input data files for visualization.

*   **FR-1.1 (H):** The system **SHALL** provide a mechanism (e.g., file upload dialog) for a user to select a local data file for visualization.
*   **FR-1.2 (H):** The system **SHALL** parse tab-delimited text files where columns represent, in order: Point ID, X-coordinate, Y-coordinate, Z-coordinate, Cluster ID, and Descriptive Information.
*   **FR-1.3 (M):** The system **SHALL** validate the basic structure of the input file (correct number of columns, numeric values in coordinate columns) and provide a clear error message to the user if the file is malformed.
*   **FR-1.4 (H):** The system **SHALL** support data files containing up to 2000 distinct data points.

#### 3.2 Feature 2: 3D Visualization Core
**Description:** The system shall render a scientifically accurate 3D grid with data points.

*   **FR-2.1 (H):** The system **SHALL** plot each data point as a distinct visual marker (e.g., sphere, cube) at its correct (X, Y, Z) coordinates within a 3D Cartesian grid.
*   **FR-2.2 (H):** The grid **SHALL** display clearly labeled axes (X, Y, Z). Axis scaling **SHALL** be automatically calculated from the data range.
*   **FR-2.3 (H):** The system **SHALL** allow the user to select a color scheme. Points **SHALL** be colored according to their Cluster ID value using the selected scheme.
*   **NFR-2.1 (H):** The initial rendering of 2000 points **SHALL** complete within 30 seconds of file load initiation on a mid-range PC.

#### 3.3 Feature 3: View Manipulation
**Description:** The user shall be able to interactively change the perspective of the 3D view.

*   **FR-3.1 (H):** The user **SHALL** be able to rotate the 3D grid freely in any direction by clicking and dragging with the mouse.
*   **FR-3.2 (H):** The user **SHALL** be able to zoom the view in and out, either via mouse wheel scroll or a designated keyboard shortcut (e.g., +/- keys).
*   **FR-3.3 (M):** The user **SHALL** be able to pan (move) the grid laterally within the viewport via mouse drag while holding a modifier key (e.g., Alt key).
*   **NFR-3.1 (H):** All view manipulation actions (rotate, zoom, pan) **SHALL** provide visual feedback with a latency of less than 2 seconds, even with 2000 points.

#### 3.4 Feature 4: Point Interaction and Information Display
**Description:** The user shall be able to select points and view their associated data.

*   **FR-4.1 (H):** A single left-click on a data point **SHALL** select it. The selected point **SHALL** be visually highlighted (e.g., increased size, glow).
*   **FR-4.2 (H):** Upon selecting a point, a dedicated information panel **SHALL** display all its associated data: Point ID, X, Y, Z coordinates, Cluster ID, and Descriptive Information.
*   **FR-4.3 (M):** The user **SHALL** be able to select multiple points simultaneously by holding a modifier key (e.g., Ctrl) while clicking. All selected points **SHALL** be highlighted.
*   **FR-4.4 (M):** When multiple points are selected, the information panel **SHALL** display the data for all selected points in a clear, comparative format (e.g., a table).

#### 3.5 Feature 5: System and Usability
**Description:** General system behavior and user interface requirements.

*   **NFR-5.1 (H):** The application client **MUST** launch and be ready for file input within 30 seconds on a mid-range PC.
*   **NFR-5.2 (M):** The user interface **SHALL** be intuitive for scientists with basic computer literacy. Common actions (load, rotate, select) **SHALL** be discoverable.
*   **NFR-5.3 (M):** The color schemes implemented **SHOULD** be chosen for clarity on screen and when printed in grayscale for publications (exact scheme TBD).

### 6. Appendices

#### Appendix A: Data File Format Specification
The input file must be a plain text file with a `.txt` or `.dat` extension. Each line represents one data point. Columns are separated by tabs (`\t`).

**Column Order:**
1.  **ID:** A unique identifier for the point (String or Integer).
2.  **X:** The X-coordinate value (Floating-point number).
3.  **Y:** The Y-coordinate value (Floating-point number).
4.  **Z:** The Z-coordinate value (Floating-point number).
5.  **Cluster:** The cluster assignment (Integer). This determines the point's color.
6.  **Description:** Free-text description or annotation for the point (String).

**Example:**
```
P001    12.5    -3.2    0.8     1       "Protein Alpha, high affinity"
P002    -1.3    8.9     2.1     2       "Protein Beta, unknown function"
```

#### Appendix B: Glossary
*   **Cluster:** A group of data points considered similar based on prior analysis.
*   **NIMR:** National Institute for Medical Research (client institution).
*   **UCL:** University College London (developing institution).
*   **Java Web Start:** A deployment technology for launching Java applications from a web browser.
