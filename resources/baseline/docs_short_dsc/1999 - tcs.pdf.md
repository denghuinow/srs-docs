### 1. Introduction

#### 1.1 Purpose
This Software Requirements Specification (SRS) document defines the functional and non-functional requirements for the Tactical Control System (TCS). It serves as a comprehensive agreement between the stakeholders—including the Program Executive Office, development teams, and end-users—and the developers. This document is intended to be used by project managers, system architects, software engineers, testers, and integrators to guide the design, implementation, verification, and validation of the TCS.

#### 1.2 Document Conventions
*   **Requirements:** Functional and non-functional requirements are uniquely identified using the format `TCS-REQ-XXX`.
*   **Keywords:** "Shall" indicates a mandatory requirement. "Should" indicates a desirable goal. "Will" indicates a statement of fact or intention.
*   **Acronyms:** Standard military and technical acronyms are used and defined in Section 1.5.

#### 1.3 Project Scope
The TCS is a joint-service, scalable command and control system for tactical Unmanned Aerial Vehicles (UAVs). Its core purpose is to provide a single system for the mission planning, control, monitoring, and data exploitation of UAVs such as Predator (MAE) and Outrider (TUAV), while ensuring interoperability with existing joint C4I systems.

**In-Scope Elements:**
*   UAV mission planning, command, control, and status monitoring.
*   Real-time control and monitoring of payloads (EO/IR/SAR).
*   Receipt, processing, and dissemination of imagery (NITF 2.0) and tactical data.
*   Integration with specified C4I systems (e.g., AFATDS, ASAS, JSTARS) via defined Interface Design Descriptions (IDDs).
*   Support for five configurable levels of UAV interaction.
*   A hardware and software architecture compliant with DII/COE and open standards.
*   Embedded training, system maintenance, and logistics support functions.

**Out-of-Scope Elements:**
*   Nuclear safety certification requirements.
*   Privacy Act requirements (deemed not applicable).
*   Detailed internal algorithmic design (deferred to detailed design documents).
*   Specification of individual Commercial Off-The-Shelf (COTS) or Non-Developmental Item (NDI) hardware components beyond adherence to defined standards.
*   Detailed protocol definitions for C4I interfaces (covered in separate IDDs).

### 2. Overall Description

#### 2.1 Product Perspective
The TCS is a standalone system that interfaces with external UAV platforms and joint C4I networks. It operates within tactical environments, including land-based shelters and shipboard installations. The system is a node within a larger intelligence and fire control network, consuming tasking and disseminating products.

#### 2.2 Product Functions (Summary)
1.  **Mission Management:** Plan, validate, upload, and monitor UAV flight missions.
2.  **Payload Control:** Operate and monitor sensor payloads; capture and tag imagery/data.
3.  **Data Handling:** Receive, process, store, and disseminate imagery and tactical messages.
4.  **C4I Interoperability:** Exchange data with external command and intelligence systems.
5.  **System Support:** Provide training simulation, fault diagnosis, maintenance aids, and secure system administration.

#### 2.3 User Characteristics
| User Class | Characteristics | Key Needs |
| :--- | :--- | :--- |
| **UAV Operator** | Trained in aviation concepts, flight planning, and UAV control. | Intuitive flight planning tools, real-time vehicle status, and control interfaces. |
| **Payload Operator** | Trained in imagery intelligence (IMINT) and sensor systems. | Real-time sensor control, high-quality video/imagery display, and annotation tools. |
| **Mission Commander** | Tactical decision-maker with joint operations knowledge. | Situational awareness, product dissemination tools, and mission oversight capabilities. |
| **Maintenance Technician** | Skilled in electronics and system hardware maintenance. | Diagnostic tools, fault isolation to LRU, and maintenance logging. |
| **Training Supervisor** | Instructor proficient in TCS operations. | Realistic simulation environments and trainee performance monitoring. |
| **System Administrator** | IT specialist with security clearance. | System configuration, user management, and secure software update procedures. |

#### 2.4 Constraints
1.  **Regulatory:** Shall comply with MIL-STD-498 for documentation and MIL-STD-882C for system safety.
2.  **Architectural:** Software shall be DII/COE compliant and use non-proprietary, open standards. Hardware shall prioritize COTS/NDI solutions.
3.  **Operational:** Must support five distinct, configurable levels of UAV interaction (e.g., from receive-only to full control).
4.  **Environmental:** Must be designed to operate within specified temperature, humidity, shock, and vibration limits for both shelter and shipboard use.
5.  **Technical:** All software and embedded firmware shall be Year 2000 compliant.

#### 2.5 Assumptions and Dependencies
*   Assumes the provision of accurate and timely digital terrain data for mission planning.
*   Dependent on government-furnished specifications for UAV communication protocols.
*   Dependent on external C4I systems providing stable, standards-compliant interfaces as defined in their respective IDDs.
*   Assumes trained personnel are available to operate and maintain the system.

### 3. System Features and Requirements

#### 3.1 Mission Planning and Control
**3.1.1 Description**
This feature allows authorized operators to create, validate, and upload flight mission plans to one or more UAVs, and to monitor and control the UAV during mission execution.

**3.1.2 Requirements**
*   `TCS-REQ-101`: The system shall provide a graphical user interface (GUI) for creating and editing UAV flight routes via waypoints.
*   `TCS-REQ-102`: The system shall perform automated terrain avoidance checks using provided digital terrain elevation data and alert the operator of potential conflicts.
*   `TCS-REQ-103`: The system shall allow the operator to upload a validated mission plan to a designated UAV via the appropriate data link.
*   `TCS-REQ-104`: The system shall display real-time UAV position, attitude, speed, altitude, and system status on a moving map display.
*   `TCS-REQ-105`: The system shall support five configurable levels of control (e.g., Level 1: Reception; Level 5: Full Control), with access enforced by user role and system configuration.

#### 3.2 Payload Operation and Exploitation
**3.2.1 Description**
This feature enables control of onboard sensors (EO, IR, SAR) and the processing, viewing, and management of collected imagery and data.

**3.2.2 Requirements**
*   `TCS-REQ-201`: The system shall provide real-time control of sensor payload pan, tilt, zoom, focus, and mode (EO/IR/SAR).
*   `TCS-REQ-202`: The system shall display real-time sensor video and metadata in a dedicated viewer.
*   `TCS-REQ-203`: The system shall allow the operator to capture still frames from video streams and automatically tag them with time, location, and sensor metadata.
*   `TCS-REQ-204`: The system shall store and manage collected imagery in NITF 2.0 format.

#### 3.3 Data Dissemination and C4I Interoperability
**3.3.1 Description**
This feature handles the formatting and transmission of intelligence products and tactical messages to external joint C4I systems.

**3.3.2 Requirements**
*   `TCS-REQ-301`: The system shall disseminate still imagery in NITF 2.0 format to pre-configured C4I systems (e.g., JSTARS, ASAS).
*   `TCS-REQ-302`: The system shall generate and receive standardized tactical messages (e.g., VMF, USMTF) to exchange tasking, reports, and alerts with systems such as AFATDS.
*   `TCS-REQ-303`: All external interfaces shall be implemented as specified in their governing Interface Design Descriptions (IDDs).

#### 3.4 System Maintenance and Diagnostics
**3.4.1 Description**
This feature supports system sustainment by enabling fault detection, isolation, and providing maintenance aids.

**3.4.2 Requirements**
*   `TCS-REQ-401`: The system shall perform continuous Built-In-Test (BIT) and Periodic BIT on its internal hardware and software components.
*   `TCS-REQ-402`: The system shall isolate detected faults to the Line Replaceable Unit (LRU) level and present diagnostic results to the maintenance technician via a maintenance GUI.
*   `TCS-REQ-403`: The system shall maintain a secure, time-stamped log of all system faults, warnings, and operator actions.

#### 3.5 Training
**3.5.1 Description**
This feature provides a simulated operational environment for training operators without requiring live UAVs or sensors.

**3.5.2 Requirements**
*   `TCS-REQ-501`: The system shall include embedded interactive courseware (ICW) for operator and maintainer training.
*   `TCS-REQ-502`: The system shall provide a simulation mode that emulates UAV flight dynamics, sensor feeds, and data link behavior.

#### 3.6 System Administration and Security
**3.6.1 Description**
This feature covers the secure management of the system software, configuration, and user access.

**3.6.2 Requirements**
*   `TCS-REQ-601`: The system shall require password-based authentication for all user accounts.
*   `TCS-REQ-602`: The system shall enforce role-based access control (RBAC), linking user roles to specific system functions and data.
*   `TCS-REQ-603`: The system shall allow a system administrator to install software updates from a CD-ROM, requiring administrator credentials to initiate the process.

### 4. Non-Functional Requirements

#### 4.1 Performance Requirements
*   `TCS-REQ-701`: The system shall support mission planning and UAV launch within 1 hour of receipt of tasking after system emplacement.
*   `TCS-REQ-702`: The system shall process and display sensor video with a latency of less than 2 seconds from sensor collection to operator display under nominal conditions.
*   `TCS-REQ-703`: The system shall be capable of controlling a minimum of [Number TBD] UAVs and [Number TBD] sensor payloads concurrently.

#### 4.2 Safety & Security Requirements
*   `TCS-REQ-704`: The system shall implement safeguards to prevent unauthorized or inadvertent transmission of UAV control commands.
*   `TCS-REQ-705`: All data at rest shall be protected in accordance with applicable data classification standards.

#### 4.3 Availability & Reliability Requirements
*   `TCS-REQ-706`: The system's Operational Availability (Ao) shall meet or exceed the thresholds specified in the Predator and Outrider ORDs.

#### 4.4 Portability & Compatibility Requirements
*   `TCS-REQ-707`: The system software shall be hostable on DII/COE-compliant computing environments.
*   `TCS-REQ-708`: The system shall achieve successful interoperability testing with all C4I systems per the approved integration schedule.
