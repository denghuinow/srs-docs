### 1. Introduction

#### 1.1 Purpose
This document defines the functional and non-functional requirements for the Publications Management System (PMS). It is intended for use by the project stakeholders, developers, testers, and project managers to ensure a common understanding of the system to be developed.

#### 1.2 Scope
The PMS is a web-based platform for managing a database of academic publications. Its core purpose is to provide controlled access to bibliographic information and full-text documents for users within the Vrije Universiteit Brussel (VUB) network and registered members. The system will support publication upload, search, viewing, and download functionalities through both web and command-line interfaces.

**In-Scope Features:**
*   Web and command-line interfaces (CLI) for system interaction.
*   User registration, authentication, and role-based access control.
*   Publication search, viewing metadata, and downloading full-text documents (PDF, PostScript).
*   Upload and editing of publications with automatic metadata extraction from supported formats.
*   Administrative and moderator functions for user, group, and publication management.

**Out-of-Scope Features:**
*   Support for document formats other than PDF, PostScript, BibTeX, and RIS (e.g., MS Word).
*   Automatic disambiguation of author or institute name aliases.
*   Management of audio or video files.
*   Automated retrieval of full-text documents from URLs provided in abstracts.
*   Extension of services to non-academic or external user bases beyond the VUB network.

#### 1.3 Definitions, Acronyms, and Abbreviations
*   **PMS:** Publications Management System.
*   **VUB:** Vrije Universiteit Brussel.

### 2. Overall Description

#### 2.1 Product Perspective
The PMS is a new, self-contained system to be deployed on the existing Linux-based Wilma server at VUB. It will interact with users via a web browser (rendering XHTML) and a command-line shell. It will manage its own database of users, publications, and metadata.

#### 2.2 User Classes and Characteristics
| User Class | Description | Key Characteristics |
| :--- | :--- | :--- |
| **Guest** | An anonymous user accessing from outside the VUB network. | Very limited access; can only view the login/registration page. |
| **VUB-Network User** | A user connected from within the VUB IP range, not necessarily logged in. | Can search the publication database and download available full-text documents. |
| **Member** | A logged-in user with a registered account. | Inherits VUB-Network User privileges; can manage personal account details. |
| **Publisher** | A logged-in Member with elevated privileges. | Can upload new publications (single/bulk), edit metadata for their own publications. |
| **Moderator** | A privileged user responsible for content quality. | Can edit publication details for assigned departments/groups, manage user levels and group permissions within their scope. |
| **Administrator** | A super-user with full system oversight. | Has full control over all users, groups, publications, and system configuration settings. |

#### 2.3 Operating Environment
*   **Server:** Must operate on the VUB's Linux-based Wilma server.
*   **Software Stack:** Must be implemented in Ruby without the use of frameworks (e.g., Rails, Sinatra). Only free software libraries and tools are permitted.
*   **Web Standard:** The web interface must generate pages compliant with W3C XHTML 1.0 Transitional.
*   **Documentation:** Source code must be documented using RDoc.

#### 2.4 Design and Implementation Constraints
1.  **Technical:** Implementation in plain Ruby, no external frameworks.
2.  **Legal:** Use of free/open-source software libraries only.
3.  **Architectural:** Design must be modular to allow for future expansion of features.
4.  **Compliance:** Web output must validate against XHTML 1.0 Transitional standards.

#### 2.5 Assumptions and Dependencies
*   The Wilma server provides a stable Linux environment with Ruby installed.
*   Network access controls for identifying "VUB-Network Users" (via IP range) are handled by the server environment.
*   Success metrics related to Wilma server downtime are outside the direct control of the PMS application.

### 3. Specific Requirements

#### 3.1 Functional Requirements

**3.1.1 User Management (UM)**
*   **UM-1:** The system shall allow a Guest to register for a new account by providing required details (e.g., name, email, password).
*   **UM-2:** The system shall allow users (Member, Publisher, Moderator, Administrator) to authenticate using a username/email and password.
*   **UM-3:** The system shall enforce role-based privileges as defined in Section 2.2.
*   **UM-4:** The system shall allow a Member to view and edit their own account profile information.
*   **UM-5:** The system shall allow an Administrator to create, view, edit, and delete any user account.
*   **UM-6:** The system shall allow an Administrator and Moderator to assign users to groups and manage group permissions.

**3.1.2 Publication Management (PM)**
*   **PM-1:** The system shall allow a Publisher to upload a new publication. The upload must include the full-text document (PDF/PS) and/or a metadata file (BibTeX/RIS).
*   **PM-2:** The system shall automatically extract and store metadata from uploaded BibTeX or RIS files.
*   **PM-3:** The system shall allow a Publisher to edit the metadata of publications they have uploaded.
*   **PM-4:** The system shall allow a Moderator to edit the metadata of publications belonging to their assigned department or group.
*   **PM-5:** The system shall allow an Administrator to edit or delete any publication.
*   **PM-6:** The system shall support bulk upload of publications by Publishers (e.g., via a ZIP file containing multiple BibTeX/files).

**3.1.3 Search and Retrieval (SR)**
*   **SR-1:** The system shall provide a search interface for VUB-Network Users, Members, Publishers, Moderators, and Administrators.
*   **SR-2:** The search function shall allow filtering by keyword(s), author name, title, year, and other relevant bibliographic fields.
*   **SR-3:** The system shall display search results in a list, showing core metadata (title, authors, year, source).
*   **SR-4:** The system shall allow users to view the full metadata record of a publication from the search results.
*   **SR-5:** The system shall allow VUB-Network Users and all logged-in roles to download the full-text document (PDF/PS) of a publication, if available.

**3.1.4 Interface Requirements (IR)**
*   **IR-1:** The system shall provide a web-based GUI accessible via standard browsers.
*   **IR-2:** The web GUI shall render valid XHTML 1.0 Transitional.
*   **IR-3:** The system shall provide a CLI for executing administrative and batch operations (e.g., bulk imports, user management scripts).

#### 3.2 Non-Functional Requirements

**3.2.1 Performance**
*   **PER-1:** The system shall have an availability of >99% during standard operational hours, excluding downtime of the underlying Wilma server.
*   **PER-2:** The automatic metadata extraction process shall succeed for at least 95% of submitted BibTeX/RIS files.
*   *Note: Specific response times and concurrent user handling are TBD (To Be Determined).*

**3.2.2 Usability**
*   **USA-1:** The system shall achieve a user satisfaction score of at least 4 out of 5 on ease of search and download functionality, as measured by post-deployment survey.

**3.2.3 Reliability**
*   The system shall maintain data integrity, ensuring no loss of publication data or user information under normal operating conditions.

**3.2.4 Security**
*   **SEC-1:** User passwords shall be stored using a strong, irreversible hashing algorithm.
*   **SEC-2:** Access to publication downloads shall be restricted as per the user role definitions (e.g., Guests cannot download).
*   **SEC-3:** The system shall be protected against common web vulnerabilities (e.g., SQL injection, cross-site scripting).

4.  Support for additional export formats for publication lists (beyond the core HTML, PDF, PS).
