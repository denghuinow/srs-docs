### 1. Introduction

#### 1.1 Purpose
This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for the **3D Biological Data Visualization System**. The primary purpose of this system is to provide research scientists, data-mining scientists, and students with an interactive three-dimensional visualization tool for investigating and comparing attributes of biological data, with a specific focus on protein-related datasets. This document is intended for use by the project stakeholders, developers, testers, and project managers.

#### 1.2 Scope
The system will be a server-side application that processes user-supplied, formatted data files to generate an interactive 3D scatter plot within a client interface. Core capabilities include rendering data points in a 3D grid, applying color coding based on data attributes, and providing direct manipulation of the visualization (rotate, zoom, pan). Detailed data point information will be available on user selection. The system must be platform-independent for major operating systems and developed to meet a critical publication deadline.

**In-Scope:**
*   Server-side processing of input data files.
*   Generation of an interactive 3D visualization client.
*   User interaction with the 3D viewport.
*   Display of metadata on point selection.

**Out-of-Scope:**
*   Editing or modifying the original data file.
*   Advanced statistical analysis or data transformation.
*   User management, authentication, or data persistence across sessions.
*   Creation or management of the biological data files themselves.

#### 1.3 Definitions, Acronyms, and Abbreviations
| Term | Definition |
| :--- | :--- |
| **3D Grid / Plot** | The three-dimensional Cartesian coordinate system where data points (X, Y, Z) are rendered. |
| **Cluster Attribute** | A categorical or numerical data column used to group and color-code data points. |
| **Point Selection** | A user action (e.g., click) to identify a specific data point for detailed inspection. |
| **Server-Side Execution** | The core application logic and computation run on a server; the client primarily handles display and interaction. |

### 2. Overall Description

#### 2.1 Product Perspective
This system is a new, standalone visualization tool designed to support scientific research. It may later be integrated into a larger suite of bioinformatics analysis tools. It operates on a client-server model where the heavy computational load of data parsing and scene graph preparation is handled server-side, delivering a lightweight interactive view to the user's client machine.

#### 2.2 Product Functions
1.  **Data Input & Parsing:** Accept and validate a structured data file from the user.
2.  **3D Rendering:** Plot validated data points in an interactive 3D coordinate system.
3.  **Visual Encoding:** Apply color to points based on a user-specified or default cluster attribute.
4.  **Viewport Manipulation:** Allow the user to rotate, zoom (dolly), and pan (move) the 3D grid.
5.  **Data Point Interrogation:** Display the name and full set of attributes for a user-selected data point.

#### 2.3 User Characteristics
| User Class | Characteristics | Key Needs |
| :--- | :--- | :--- |
| **Research Scientist** | Expert in biology/proteomics. Moderate computer literacy. | Intuitive visualization, accurate data representation, ability to explore spatial relationships. |
| **Data-Mining Scientist** | Strong computational/statistical background. | Clear visual clustering, interaction to test hypotheses, precise point identification. |
| **Student** | Learning proteomics concepts. Variable technical skill. | Easy-to-use interface, clear labeling, educational exploration of datasets. |

All users require the system to be reliable and the visualization to be performant with typical dataset sizes.

#### 2.4 Constraints
1.  **Platform Constraint:** The application must be deployable and fully functional on both **Windows** and **Linux** operating systems.
2.  **Architecture Constraint:** Application execution and core logic **must be kept server-side**. The client component should be as lightweight as possible.
3.  **Schedule Constraint:** The system must be developed, tested, and ready for use to support a **publication deadline in March 2005**. This imposes a fixed and immovable project completion date.

#### 2.5 Assumptions and Dependencies
*   **Assumption:** Users will provide data files in the pre-defined, correct format.
*   **Assumption:** Standard graphical libraries (e.g., OpenGL bindings) are available on the server for 3D scene generation.
*   **Dependency:** The project is dependent on the selection of a suitable, cross-platform technology stack for server-side 3D graphics processing (e.g., VTK, Java 3D, custom solution with OpenGL).
*   **Dependency:** Client machines will have a standard web browser or a lightweight runtime environment (e.g., Java Web Start) to display the visualization.

### 3. Specific Requirements

#### 3.1 Functional Requirements

##### 3.1.1 Data Input and Processing
*   **FR1.1:** The system shall accept a single input data file in the format specified in Appendix A.
*   **FR1.2:** The system shall validate the input file for correct formatting, required columns (X, Y, Z, Point Name, Cluster ID), and data integrity.
*   **FR1.3:** Upon successful validation, the system shall parse the file and prepare the data structure for visualization.

##### 3.1.2 3D Visualization Generation
*   **FR2.1:** The system shall generate a 3D scatter plot with axes labeled according to the input data dimensions (e.g., "Component 1", "Component 2", "Component 3").
*   **FR2.2:** Each data point shall be plotted at its corresponding (X, Y, Z) coordinates.
*   **FR2.3:** Data points shall be colored according to the "Cluster ID" attribute. A distinct, visually separable color palette shall be used.

##### 3.1.3 User Interaction with Visualization
*   **FR3.1:** The user shall be able to rotate the 3D plot freely along all axes using a click-and-drag mouse interaction.
*   **FR3.2:** The user shall be able to zoom the view in and out using the mouse scroll wheel or a designated keyboard shortcut.
*   **FR3.3:** The user shall be able to pan (move the grid laterally and vertically) across the scene using a click-and-drag interaction with a modifier key (e.g., Shift + Drag).

##### 3.1.4 Data Point Selection and Information Display
*   **FR4.1:** The user shall be able to select a single data point by clicking on it.
*   **FR4.2:** Upon selection, the selected point shall be visually highlighted (e.g., increased size, glow effect).
*   **FR4.3:** A dedicated information panel or pop-up display shall show the following details for the selected point:
    *   Point Name
    *   X, Y, Z coordinates
    *   Cluster ID
    *   All other attributes present in the input file for that point.

#### 3.2 Non-Functional Requirements

##### 3.2.1 Performance Requirements
*   **PERF-1:** The system shall render and display a visualization for a dataset of up to **10,000 points** within 5 seconds of file submission on standard server hardware (circa 2004-2005).
*   **PERF-2:** User interactions (rotate, zoom, pan) shall have a perceived latency of less than 100ms to maintain interactivity.

##### 3.2.2 Design Constraints
*   **DC-1:** The application shall be developed using cross-platform technologies to satisfy requirement 2.4.1.
*   **DC-2:** The system architecture shall enforce server-side execution as per requirement 2.4.2. No core plotting logic shall be offloaded to the client.

##### 3.2.3 Software System Attributes
*   **Reliability:** The system shall be available for use during standard research hours. It shall handle malformed files gracefully with informative error messages without crashing.
*   **Usability:** The interface shall be intuitive enough for a scientist to use with less than 15 minutes of familiarization. Visual feedback for all actions is required.
*   **Portability:** The server component must be easily installable and configurable on both Windows (2000/XP) and Linux (kernel 2.4+) systems.
*   **Schedule:** The final, tested system must be delivered by **February 28, 2005**, to allow time for final validation prior to the March publication deadline.

### 4. Appendix

#### Appendix A: Input Data File Format
The system expects a tab-delimited text file (.txt or .tsv) with a header row. The following columns are mandatory:

1.  **Point_Name:** A unique identifier for the data point (e.g., protein identifier).
2.  **X:** Numerical value for the X-axis coordinate.
3.  **Y:** Numerical value for the Y-axis coordinate.
4.  **Z:** Numerical value for the Z-axis coordinate.
5.  **Cluster_ID:** An integer or string representing the cluster/group membership for coloring.

Additional columns may be present and will be displayed in the point detail view.

**Example:**
```
Point_Name    X        Y        Z    Cluster_ID    P_Value    Description
Prot_Alpha    1.45    -0.23    3.12    1            0.001     Kinase
Prot_Beta    -2.10    1.85    0.54     2            0.045     Receptor
Prot_Gamma    0.89    2.30    -1.22    1            0.000     Transcription Factor
```
