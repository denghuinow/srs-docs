# Software Requirements Specification (SRS)
## Unified Tactical UAV Command & Control (UTUC2) System

**Document Version:** 1.0
**Date:** 2023-10-27
**Status:** Draft for Review

---

### 1. Introduction

#### 1.1 Purpose
This Software Requirements Specification (SRS) document defines the functional and non-functional requirements for the Unified Tactical UAV Command & Control (UTUC2) System. It is intended to serve as a comprehensive guide for stakeholders, developers, testers, and project managers throughout the system's development lifecycle.

#### 1.2 Document Conventions
*   **Requirements IDs:** Follow the format `FR-XXX` for Functional Requirements and `NFR-XXX` for Non-Functional Requirements.
*   **Keywords:** `MUST`, `SHALL`, `REQUIRED` indicate mandatory requirements. `SHOULD`, `RECOMMENDED` indicate desirable but not mandatory features. `MAY`, `OPTIONAL` indicate permissible actions.
*   **Acronyms:**
    *   **UAV:** Unmanned Aerial Vehicle
    *   **C4I:** Command, Control, Communications, Computers, and Intelligence
    *   **DII/COE:** Defense Information Infrastructure/Common Operating Environment
    *   **UTUC2:** Unified Tactical UAV Command & Control

#### 1.3 Project Scope
The UTUC2 System provides a unified software solution for the command, control, and data processing of multiple tactical UAV platforms. The in-scope elements are:

*   **Platform Control:** Direct control and monitoring of the Predator and Outrider UAV models.
*   **Interoperability:** Standardized interfaces for data exchange with specified external C4I systems.
*   **Interaction Levels:** Full support for all five defined levels of UAV interaction (as detailed in Section 3.2).
*   **Core Workflows:** Mission Planning, Real-Time Mission Control & Monitoring, Payload Data Management, and System Maintenance.

Out-of-scope elements include: manufacturing of UAV hardware, development of external C4I systems, and satellite communication link provisioning.

### 2. Overall Description

#### 2.1 Product Perspective
The UTUC2 System is a mission-critical component within a larger network-centric warfare architecture. It operates as a standalone application suite compliant with the DII/COE, integrating with external C4I systems (e.g., AFATDS, GCCS-J) for tasking and reporting, and interfacing with UAV-specific datalinks for platform control.

#### 2.2 Product Functions
The high-level capabilities of the system are:
1.  **Mission Planning:** Create, edit, validate, and store flight plans and mission parameters.
2.  **Mission Control & Monitoring:** Provide real-time telemetry display, command transmission, and alerting for in-flight UAVs.
3.  **Payload Product Management:** Control sensor payloads (EO/IR, SAR), receive, process, exploit, and disseminate collected data.
4.  **C4I System Interface:** Send and receive standardized messages (e.g., mission tasks, situation reports) to/from authorized external systems.
5.  **System Administration:** Manage user roles, permissions, system configuration, and logs.

#### 2.3 User Classes and Characteristics
| User Class | Characteristics | Key Responsibilities |
| :--- | :--- | :--- |
| **Mission Planner** | Highly trained in airspace, routing, and payload effects. | Creates and validates mission plans; defines mission objectives and rules of engagement. |
| **UAV Operator (Pilot)** | Certified on specific UAV platforms (Predator/Outrider). | Executes pre-planned missions; performs real-time manual control; monitors UAV health & status. |
| **Payload Operator** | Trained in specific sensor systems and imagery analysis. | Controls payloads; monitors data feeds; performs initial exploitation and tagging. |
| **Maintenance Technician** | Skilled in system hardware and software diagnostics. | Performs system startup/shutdown procedures; conducts routine maintenance; diagnoses faults. |
| **System Administrator** | Expert in network and DII/COE security. | Manages user accounts, system access controls, and software updates. |

#### 2.4 Operating Environment
*   **Software:** MUST operate on the standard DII/COE hardware and software baseline.
*   **Hardware:** Expected to run on ruggedized COTS workstations within a tactical operations center.
*   **Networks:** MUST operate over secure military IP networks (e.g., SIPRNet) and dedicated UAV datalink frequencies.

#### 2.5 Design and Implementation Constraints
1.  **Compliance:** The system SHALL be fully compliant with the DII/COE architecture, standards, and security policies.
2.  **Interfaces:** The system SHALL implement interfaces as defined in the ICDs for the following C4I systems: [List specified C4I systems, e.g., GCCS-J, AFATDS, DCGS].
3.  **Operational States:** The system SHALL support the following defined states with maximum transition times:
    *   **Startup to Operations Ready:** ≤ 5 minutes.
    *   **Operations to Shutdown:** ≤ 3 minutes.
    *   **Operations to Degraded Mode (upon critical failure):** ≤ 30 seconds.

#### 2.6 Assumptions and Dependencies
*   **Assumption:** Required C4I systems will be available on the network and provide compliant interfaces.
*   **Assumption:** UAV datalink hardware and encryption devices will be provided and functional.
*   **Dependency:** The project depends on timely access to UAV platform API specifications from the manufacturers.

### 3. System Features and Requirements

#### 3.1 Mission Planning (FR-100 Series)
*   **FR-101:** The system SHALL allow a Mission Planner to create a flight plan by defining a sequence of waypoints (latitude, longitude, altitude) for Predator and Outrider UAVs.
*   **FR-102:** The system SHALL perform automated validation of flight plans against no-fly zones, terrain data, and platform-specific performance envelopes.
*   **FR-103:** The system SHALL enable the assignment of specific payload actions (e.g., sensor point, start recording) to waypoints or loiter patterns.

#### 3.2 Mission Control and Monitoring (FR-200 Series)
*   **FR-201:** The system SHALL provide a real-time, geospatial map display showing the position, track, and orientation of all controlled UAVs.
*   **FR-202:** The system SHALL support the five defined levels of UAV interaction:
    1.  **Level 1:** Indirect Receipt of UAV Product.
    2.  **Level 2:** Direct Receipt of UAV Product.
    3.  **Level 3:** Control of UAV Payload.
    4.  **Level 4:** Control of UAV.
    5.  **Level 5:** Control of UAV Launch and Recovery.
*   **FR-203:** The system SHALL provide audible and visual alerts for predefined critical conditions (e.g., lost link, engine fault, fuel low).

#### 3.3 Payload Product Management (FR-300 Series)
*   **FR-301:** The system SHALL display real-time video streams from EO/IR and SAR payloads in dedicated viewer windows.
*   **FR-302:** The system SHALL allow a Payload Operator to tag imagery with metadata (coordinates, time, classification) and generate standard product files.
*   **FR-303:** The system SHALL provide tools for basic image manipulation (zoom, contrast, pan).

#### 3.4 C4I System Interface (FR-400 Series)
*   **FR-401:** The system SHALL receive and parse mission tasking orders in [specified format, e.g., USMTF] from authorized C4I systems.
*   **FR-402:** The system SHALL transmit mission status reports and essential elements of information (EEIs) to authorized C4I systems at configurable intervals or upon event triggers.

### 4. External Interface Requirements

#### 4.1 User Interfaces
*   The primary interface SHALL be a graphical user interface (GUI) with multiple viewports for map, video, telemetry, and alert displays.
*   The GUI SHALL be operable via mouse, keyboard, and tactical joystick for manual UAV control.

#### 4.2 Hardware Interfaces
*   The system SHALL interface with a KIV-7/19 or equivalent encryption device for secure communications.
*   The system SHALL interface with UAV-specific ground data terminal (GDT) hardware for datalink control.

#### 4.3 Software Interfaces
*   **SIF-001:** Interface to GCCS-J for receiving ATO data and sending UNITREPs. Protocol: TADIL-J (VMF) over TCP/IP.
*   **SIF-002:** Interface to UAV Datalink. Protocol: Platform-specific binary protocol via serial/USB.

#### 4.4 Communications Interfaces
*   The system SHALL communicate over TCP/IP on the SIPRNet backbone.
*   UAV command & control uplink/downlink SHALL use Ku-band/S-band frequencies as defined by the platform.

### 5. Non-Functional Requirements

#### 5.1 Performance Requirements
*   **NFR-001 (Latency):** The time from operator command initiation to its transmission on the UAV datalink SHALL be ≤ 500 milliseconds.
*   **NFR-002 (Refresh):** Telemetry and vehicle position on the map display SHALL update at a minimum of 1 Hz.
*   **NFR-003 (Capacity):** The system SHALL support simultaneous control and monitoring of up to 4 UAVs (mixed Predator/Outrider) from a single operator station.

#### 5.2 Safety Requirements
*   **NFR-010:** The system SHALL include a "Lost Link" procedure that automatically commands the UAV to execute a pre-programmed, safe loiter pattern.

#### 5.3 Security Requirements
*   **NFR-020:** The system SHALL enforce role-based access control (RBAC) as per DII/COE standards. An operator SHALL NOT be able to command a UAV without being logged in with a "Pilot" role for that specific platform.
*   **NFR-021:** All data at rest (mission plans, logs) SHALL be encrypted using FIPS 140-2 validated cryptographic modules.

#### 5.4 Software Quality Attributes
*   **Reliability:** Mean Time Between Critical Failures (MTBCF) SHALL be ≥ 1000 hours.
*   **Availability:** The system SHALL have an operational availability of 99.5% during mission periods.
*   **Maintainability:** All system logs and fault codes SHALL be accessible via a unified diagnostic console for maintenance personnel.
