# Software Requirements Specification (SRS)
## For the JSE Automated ISIN Lifecycle Management System

**Document Version:** 1.0
**Date:** 2023-10-27
**Status:** Draft for Review

---

### 1. Introduction

#### 1.1 Purpose
This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for the **JSE Automated ISIN Lifecycle Management System**. This system is designed to automate the issuance, cancellation, and de-registration of ISIN (International Securities Identification Number) codes for dematerialized money market instruments, acting as the National Numbering Agent (NNA) for the Johannesburg Stock Exchange (JSE). The primary audience for this document includes the project stakeholders, system architects, developers, and testers.

#### 1.2 Scope
The scope of this system is strictly limited to the electronic exchange of standardized SWIFT MT598 messages between **STRATE** (the Central Securities Depository and requestor) and the **JSE** (the National Numbering Agent and service provider). The system will:
*   Receive, validate, and process incoming SWIFT MT598 requests from STRATE.
*   Automatically perform the requested ISIN lifecycle action (Issue, Cancel, De-register).
*   Generate and transmit the appropriate SWIFT MT598 response back to STRATE.
*   Maintain an audit log of all requests, actions, and responses.

**Out of Scope:**
*   User interfaces for manual ISIN management.
*   Communication channels other than the pre-defined SWIFT MT598 format.
*   Lifecycle management for non-money market instruments or physical securities.
*   Integration with other internal JSE or STRATE systems beyond the specified message gateway.

#### 1.3 Definitions, Acronyms, and Abbreviations
| Term | Definition |
| :--- | :--- |
| **ANNA** | Association of National Numbering Agencies. The global federation of NNAs. |
| **ISIN** | International Securities Identification Number. A 12-character alphanumeric code that uniquely identifies a security. |
| **ISO 6166** | The international standard defining the structure and governance of ISINs. |
| **JSE** | Johannesburg Stock Exchange. The National Numbering Agent (NNA) for South Africa. |
| **MT598** | A specific SWIFT (Society for Worldwide Interbank Financial Telecommunication) message type used for free-format messages, often adapted for specific workflows. |
| **NNA** | National Numbering Agency. An organization appointed in a country to allocate ISINs. |
| **STRATE** | South Africa's central securities depository (CSD). |

### 2. Overall Description

#### 2.1 Product Perspective
This system is a standalone, automated message processing engine. It will interface directly with the JSE's existing SWIFT messaging infrastructure. It acts as a critical regulatory and operational component within the South African financial market infrastructure, ensuring efficient and compliant ISIN management.

#### 2.2 User Classes and Characteristics
| User Class | Characteristics | Key Interactions |
| :--- | :--- | :--- |
| **STRATE (System Actor)** | External entity. Initiates all requests via automated SWIFT messages. Requires guaranteed delivery and timely, accurate responses. | Sends MT598 requests for Issue, Cancel, De-register. Receives MT598 confirmations/acknowledgments. |
| **JSE Operations Staff** | Internal user. Monitors system health, reviews error logs, and handles exceptional cases that cannot be resolved automatically. | Accesses system logs and dashboards. Manually intervenes on failed or rejected messages. |
| **System Administrator** | Internal user. Responsible for deployment, configuration, maintenance, and user access management. | Configures system parameters, manages connectivity, performs backups. |

#### 2.3 Operating Environment
*   **Hardware:** To be deployed on JSE-approved virtualized or physical servers.
*   **Software:** Will run on a JSE-standard enterprise operating system (e.g., RHEL, Windows Server). Must integrate with the existing JSE SWIFT Alliance Gateway or equivalent.
*   **Networks:** Operates within the JSE's secure internal network with a dedicated, secure connection to the SWIFT network.

#### 2.4 Design and Implementation Constraints
1.  **Messaging Protocol:** All communication **MUST** use the specific, pre-defined SWIFT MT598 message formats agreed upon between STRATE and JSE.
2.  **Compliance:** ISIN generation and validation **MUST** strictly comply with ANNA guidelines and ISO 6166 standards.
3.  **Automation:** The core processing of valid requests **MUST** be fully automated, requiring no manual intervention under normal conditions.

#### 2.5 Assumptions and Dependencies
*   **Assumption:** STRATE will always send well-formed MT598 messages according to the jointly agreed specification.
*   **Assumption:** The volume of requests will remain within the estimated range of 200-500 issuances per day, with predictable peaks.
*   **Dependency:** The system is dependent on the continuous availability and stability of the JSE's SWIFT messaging infrastructure.
*   **Dependency:** A pre-agreed mapping or algorithm for generating the ISIN's 9-character alphanumeric security identifier (part of the full ISIN) is available and will be implemented.

### 3. System Features and Requirements

#### 3.1 Feature 1: ISIN Issuance
**Description:** The system shall automatically issue a new, valid ISIN code in response to a valid SWIFT MT598 issuance request from STRATE.

**3.1.1 Functional Requirements**
| ID | Requirement Description | Priority |
| :--- | :--- | :--- |
| **F1.1** | The system shall receive an incoming SWIFT MT598 message tagged as an `ISIN Issuance Request`. | High |
| **F1.2** | The system shall validate the message structure against the predefined MT598 format specification. | High |
| **F1.3** | The system shall validate all mandatory data fields within the request (e.g., instrument type, issuer, maturity date, currency). | High |
| **F1.4** | The system shall generate a 12-character ISIN that complies with ISO 6166: <br> `[ZA] + [9-character Security Identifier] + [1 Check Digit]`. | High |
| **F1.5** | The system shall ensure the generated ISIN is unique and not currently active in its repository. | High |
| **F1.6** | Upon successful generation, the system shall record the ISIN, link it to all request data, and mark its status as `ISSUED`. | High |
| **F1.7** | The system shall construct and send a SWIFT MT598 `Issuance Confirmation` message back to STRATE, containing the new ISIN. | High |
| **F1.8** | If validation fails (F1.2, F1.3), the system shall send a SWIFT MT598 `Rejection` message to STRATE with an appropriate error code and description. | High |

#### 3.2 Feature 2: ISIN Cancellation / De-issuance
**Description:** The system shall cancel or de-issue an existing ISIN based on a valid request from STRATE, rendering it invalid for future use.

**3.2.1 Functional Requirements**
| ID | Requirement Description | Priority |
| :--- | :--- | :--- |
| **F2.1** | The system shall receive an incoming SWIFT MT598 message tagged as an `ISIN Cancellation Request`. | High |
| **F2.2** | The system shall validate that the ISIN provided in the request exists in its repository and is in an `ISSUED` state. | High |
| **F2.3** | The system shall update the status of the ISIN to `CANCELLED` and record the reason and timestamp. | High |
| **F2.4** | The system shall construct and send a SWIFT MT598 `Cancellation Confirmation` message back to STRATE. | High |
| **F2.5** | If the ISIN is not found or is not in an issuable state (e.g., already matured), the system shall send a SWIFT MT598 `Rejection` message. | High |

#### 3.3 Feature 3: ISIN De-registration at Maturity
**Description:** The system shall automatically de-register an ISIN for an instrument that has reached its maturity date.

**3.3.1 Functional Requirements**
| ID | Requirement Description | Priority |
| :--- | :--- | :--- |
| **F3.1** | The system shall receive an incoming SWIFT MT598 message tagged as an `ISIN Maturity / De-registration Request`. | High |
| **F3.2** | The system shall validate that the ISIN provided exists and that its recorded maturity date matches the request. | High |
| **F3.3** | The system shall update the status of the ISIN to `DE-REGISTERED (MATURED)` and record the timestamp. | High |
| **F3.4** | The system shall construct and send a SWIFT MT598 `De-registration Confirmation` message back to STRATE. | High |

#### 3.4 Feature 4: Audit Logging and Monitoring
**Description:** The system shall maintain a complete, immutable record of all activities for operational and compliance purposes.

**3.4.1 Functional Requirements**
| ID | Requirement Description | Priority |
| :--- | :--- | :--- |
| **F4.1** | The system shall log every incoming SWIFT MT598 message in its raw form with a timestamp and unique message ID. | Medium |
| **F4.2** | The system shall log every action taken (e.g., "ISIN XYZ123 issued", "Validation failed for field X") and every outgoing message. | Medium |
| **F4.3** | The system shall provide a secure interface for JSE Operations Staff to view, search, and filter these logs. | Medium |

### 4. Non-Functional Requirements

#### 4.1 Performance Requirements
| ID | Requirement Description |
| :--- | :--- |
| **PER-1** | The system shall process **95%** of valid ISIN issuance requests within **2 seconds** of message receipt, under peak load (500 requests/day, unevenly distributed). |
| **PER-2** | The system shall be available **99.5%** of the time during market operating hours (06:00 - 18:00 SAST, Monday-Friday). |
| **PER-3** | The system's database shall be capable of storing a minimum of 5 years of ISIN records and transaction logs without performance degradation. |

#### 4.2 Security Requirements
| ID | Requirement Description |
| :--- | :--- |
| **SEC-1** | All SWIFT message exchanges must occur over the secure, authenticated SWIFT network. |
| **SEC-2** | Access to system logs, administrative functions, and the ISIN repository shall be controlled via JSE's central identity and access management system (e.g., Active Directory). |
| **SEC-3** | All system data at rest (logs, database) must be encrypted using industry-standard algorithms. |

#### 4.3 Compliance Requirements
| ID | Requirement Description |
| :--- | :--- |
| **COM-1** | The ISIN generation logic shall be formally validated to ensure 100% compliance with ISO 6166 and ANNA standards. |
| **COM-2** | The system shall maintain audit trails sufficient to meet JSE internal audit and external regulatory requirements. |

#### 4.4 Reliability and Maintainability
| ID | Requirement Description |
| :--- | :--- |
| **REL-1** | The system shall implement automated monitoring of its key components and alert JSE Operations Staff in case of failure. |
| **REL-2** | The system shall be designed to allow for updates to the SWIFT MT598 format specification with minimal code changes (e.g., using configuration files). |
