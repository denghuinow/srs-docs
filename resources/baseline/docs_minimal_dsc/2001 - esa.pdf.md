### 1. Introduction

#### 1.1 Purpose
This Software Requirements Specification (SRS) document defines the functional and non-functional requirements for the ASPERA-3 Ground Data Processing Facility (GDPF). This system is responsible for the end-to-end processing of telemetry data from the ASPERA-3 instrument aboard the Mars Express spacecraft. The intended audience includes the ASPERA-3 science team, software developers, system architects, and project managers.

#### 1.2 Scope
The ASPERA-3 GDPF is a mission-critical software system that will:
*   Acquire raw telemetry data from the European Space Operations Centre (ESOC).
*   Process science, engineering, and ancillary data into a standardized, validated format (IDFS).
*   Manage the archival of all data products.
*   Facilitate the distribution of data to the science team and to the NASA Planetary Data System (PDS).
*   Provide web-based interfaces for both public outreach and protected science analysis.

**Out-of-Scope:**
*   The generation of raw telemetry at ESOC.
*   The operation of the Mars Express spacecraft or the ASPERA-3 instrument.
*   The long-term archival infrastructure of the PDS itself.

### 2. Overall Description

#### 2.1 Product Perspective
The GDPF is a standalone system that interfaces with several external entities:
*   **ESOC:** As the source of raw TM data files (ASPERA-3 and S/C orbit/attitude).
*   **PDS:** As the final archive for validated IDFS data.
*   **Science Team/Co-Is:** As consumers of IDFS data and web analysis tools.
*   **Public Internet Users:** As viewers of approved public web displays.

#### 2.2 Product Functions
The core high-level functions are:
1.  **Data Acquisition:** Automated pull or reception of TM data streams/files from ESOC.
2.  **Data Processing:** Conversion of raw TM to calibrated, time-ordered IDFS products.
3.  **Data Distribution:** Electronic delivery of IDFS to the science team and submission to PDS.
4.  **Data Archival:** Local, organized storage of all input TM and output IDFS.
5.  **Web Services:** Provision of password-protected (science) and public (outreach) data displays.

#### 2.3 User Characteristics
| User Class | Expertise | Key Tasks |
| :--- | :--- | :--- |
| **ASPERA-3 Science Team / Co-Investigators** | Expert in instrument science and data analysis. | Access and download IDFS data; use advanced web tools for preliminary analysis; validate data for PDS submission. |
| **GDPF System Operator** | Trained in system administration and operations. | Monitor processing pipelines; manage user accounts; troubleshoot failures; initiate manual reprocessing. |
| **Public User** | General public, interested in Mars exploration. | View pre-generated plots, images, and summaries of released data. |

#### 2.4 Constraints
1.  **Regulatory:** IDFS data must be formatted and delivered to the NASA PDS within **6 months** of ground receipt.
2.  **Performance:** IDFS data sets must be delivered to Co-Investigators via electronic distribution within **24 hours** of receiving error-free telemetry.
3.  **Security:** Science analysis web displays and data access points must be secured via authentication until the relevant data is authorized for public release.
4.  **Technical:** The system must be deployed and operated on the pre-specified UNIX-based production and development hardware/OS platforms.
5.  **Interface:** The system must comply with the ESOC and PDS interface specifications.

#### 2.5 Assumptions and Dependencies
*   ESOC will provide telemetry data in the agreed-upon format and via the agreed-upon delivery mechanism (e.g., FTP, SFTP).
*   The NASA PDS data standards (for IDFS) will remain stable for the duration of the mission's active phase.
*   Necessary UNIX system privileges and network configurations will be provided by the hosting facility.

### 3. Specific Requirements

#### 3.1 Functional Requirements

##### 3.1.1 Data Acquisition (DA)
*   **DA-1:** The system shall automatically connect to the designated ESOC server daily to check for and retrieve new ASPERA-3 telemetry files.
*   **DA-2:** The system shall automatically connect to the designated ESOC server daily to check for and retrieve new Mars Express orbit and attitude telemetry files.
*   **DA-3:** Upon retrieval, the system shall verify file integrity (e.g., checksum) and log the acquisition event.

##### 3.1.2 Data Processing (DP)
*   **DP-1:** The system shall process raw ASPERA-3 science telemetry through calibration algorithms to produce Level 1 IDFS products.
*   **DP-2:** The system shall merge processed science data (DP-1) with S/C orbit and attitude data (DA-2) to produce Level 2 IDFS products.
*   **DP-3:** The system shall process ASPERA-3 engineering telemetry into human-readable housekeeping IDFS reports.
*   **DP-4:** The processing pipeline shall generate comprehensive processing logs, noting any anomalies or errors encountered.
*   **DP-5:** The system shall allow for the manual reprocessing of any data set by a system operator.

##### 3.1.3 Data Archival (AR)
*   **AR-1:** The system shall maintain a local, organized archive of all raw telemetry files received from ESOC.
*   **AR-2:** The system shall maintain a local, organized archive of all generated IDFS products (Level 1, Level 2, engineering).
*   **AR-3:** The archival system shall prevent the unauthorized deletion or modification of primary data products.

##### 3.1.4 Data Distribution (DD)
*   **DD-1:** Upon successful generation of an IDFS data set, the system shall automatically notify registered Co-Investigators of its availability.
*   **DD-2:** The system shall provide a secure mechanism (e.g., authenticated download) for Co-Investigators to retrieve IDFS data sets.
*   **DD-3:** The system shall prepare and validate IDFS data sets according to NASA PDS standards.
*   **DD-4:** The system shall submit validated PDS data bundles to the NASA PDS archive. The submission must occur no later than **6 months** after the associated telemetry was acquired from ESOC.

##### 3.1.5 Web Interface (WEB)
*   **WEB-1:** The system shall provide a public-facing website displaying pre-generated plots, mission status, and released findings.
*   **WEB-2:** The system shall provide a password-protected science portal for the ASPERA-3 team.
*   **WEB-3:** The science portal (WEB-2) shall provide tools to search, browse, and visualize IDFS data (e.g., time-series plots, spectrograms).
*   **WEB-4:** Access to data within the science portal shall be configurable, allowing the PI team to control when specific data sets become visible on the public site (WEB-1).

#### 3.2 Non-Functional Requirements

##### 3.2.1 Performance
*   **PER-1:** The time from receipt of final telemetry for a given orbit to the availability of the corresponding IDFS for Co-I download shall not exceed **24 hours** under normal operating conditions.
*   **PER-2:** Web page loads for data displays shall render in under 5 seconds for 95% of requests.

##### 3.2.2 Security
*   **SEC-1:** All user authentication shall be performed over encrypted connections (HTTPS/TLS).
*   **SEC-2:** Science team passwords shall be stored using strong, salted cryptographic hashes.
*   **SEC-3:** The system shall implement role-based access control (RBAC) distinguishing at least between: Public, Science User, and System Operator.

##### 3.2.3 Reliability & Availability
*   **REL-1:** The automated data acquisition and processing pipeline shall have an uptime of 99.5% during scheduled mission operations periods.
*   **REL-2:** The system shall implement automated retry logic for transient failures in data acquisition from ESOC.

##### 3.2.4 Operational
*   **OPE-1:** The system shall be deployable and operable on the specified UNIX production servers (`prod-server-01`, `prod-server-02`).
*   **OPE-2:** All system components shall be controllable via command-line interface (CLI) for scripting and automated operations.

##### 3.2.5 Data Management
*   **DAT-1:** All IDFS products shall conform to the version of the NASA PDS standard specified in the Mission Data Management Plan.
*   **DAT-2:** A complete audit trail (logs of acquisition, processing, distribution) shall be maintained for a minimum of 7 years.
