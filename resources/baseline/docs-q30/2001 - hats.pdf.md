## 1. Introduction

### 1.1 Purpose
This document specifies the requirements for HATS-GUI, a platform-independent graphical interface for the High Assurance Transformation System (HATS). The SRS serves as a contract between developers and stakeholders, ensuring all parties have a common understanding of the system's capabilities and constraints.

### 1.2 Scope
HATS-GUI provides a graphical interface that simplifies user interaction with transformation-based software development. The system:
- **Includes**: Application management, parsing of transformation programs and target files, transformation execution, SDT and pretty-printed output display and manipulation
- **Excludes**: Transformation logic implementation (handled by HATS-SML), HATS-SML installation management

### 1.3 Definitions and Acronyms
- **HATS**: High Assurance Transformation System
- **HATS-GUI**: HATS Graphical User Interface
- **HATS-SML**: HATS Standard Meta Language component
- **SDT**: Syntax Directed Translation
- **JVM**: Java Virtual Machine
- **ML**: Meta Language

## 2. Overall Description

### 2.1 Product Perspective
HATS-GUI is a Java-based front-end component that interfaces with the existing HATS-SML transformation engine. It replaces a prototype system that lacked portability and adequate output display capabilities.

### 2.2 Product Functions
- Application lifecycle management
- Transformation program and target file parsing
- Transformation execution coordination
- SDT and text output visualization
- Display configuration management
- Search functionality across outputs

### 2.3 User Characteristics
**Primary Users:** Sophisticated researchers and developers with expertise in transformation-based software development. Users possess:
- Advanced understanding of transformation systems
- Technical proficiency with development tools
- Minimal need for extensive help systems or tutorials

### 2.4 Operating Environment
**Supported Platforms:**
- Windows 2000
- Solaris
- Linux

**Required Software:**
- Java Virtual Machine (JVM)
- ML interpreter
- HATS-SML version 2.0

### 2.5 Design and Implementation Constraints
- Must be implemented in Java for platform independence
- Must interface with HATS-SML version 2.0
- Single-user operation only
- Requires hierarchical file system

## 3. System Features

### 3.1 Application Management
**3.1.1 Description**
Users can create, open, save, and delete transformation applications.

**3.1.2 Requirements**
- **GUI-AM-001:** The system shall provide functionality to create new transformation applications
- **GUI-AM-002:** The system shall allow opening existing applications from file system
- **GUI-AM-003:** The system shall provide save functionality for current application state
- **GUI-AM-004:** The system shall allow deletion of applications with confirmation

### 3.2 File Parsing
**3.2.1 Description**
The system parses transformation language programs and target files for processing.

**3.2.2 Requirements**
- **GUI-FP-001:** The system shall parse transformation language programs for syntactic validity
- **GUI-FP-002:** The system shall parse target files for processing
- **GUI-FP-003:** The system shall provide error reporting for parsing failures

### 3.3 Transformation Execution
**3.3.1 Description**
Users can execute transformation programs through the interface.

**3.3.2 Requirements**
- **GUI-TE-001:** The system shall initiate transformation execution through HATS-SML
- **GUI-TE-002:** The system shall provide execution status feedback
- **GUI-TE-003:** The system shall support concurrent operations during transformation execution

### 3.4 SDT Output Display and Manipulation
**3.4.1 Description**
The system displays and allows manipulation of Syntax Directed Translation outputs.

**3.4.2 Requirements**
- **GUI-SDT-001:** The system shall display SDT structures graphically
- **GUI-SDT-002:** The system shall allow expansion/collapse of SDT nodes
- **GUI-SDT-003:** The system shall support navigation through large SDT structures
- **GUI-SDT-004:** The system shall meet performance targets for SDT display

### 3.5 Pretty-Printed Text Output
**3.5.1 Description**
The system displays and allows manipulation of pretty-printed text outputs.

**3.5.2 Requirements**
- **GUI-TXT-001:** The system shall display pretty-printed text outputs
- **GUI-TXT-002:** The system shall support text search functionality
- **GUI-TXT-003:** The system shall allow text navigation and selection

### 3.6 Display Configuration
**3.6.1 Description**
Users can configure SDT display settings for optimal visualization.

**3.6.2 Requirements**
- **GUI-DC-001:** The system shall allow configuration of SDT node colors
- **GUI-DC-002:** The system shall allow configuration of SDT node shapes
- **GUI-DC-003:** The system shall allow configuration of expansion levels
- **GUI-DC-004:** The system shall persist display settings between sessions

### 3.7 Search Functionality
**3.7.1 Description**
The system provides search capabilities across SDT structures and text outputs.

**3.7.2 Requirements**
- **GUI-SR-001:** The system shall provide search functionality within SDT structures
- **GUI-SR-002:** The system shall provide search functionality within text outputs
- **GUI-SR-003:** The system shall highlight search results
- **GUI-SR-004:** The system shall support navigation between search results

## 5. Non-Functional Requirements

### 5.1 Performance Requirements
- **PERF-001:** Display of 10,000-node SDT structures shall complete within ≤5 seconds
- **PERF-002:** Display of 1,000,000-node SDT structures shall complete within the same time frame (±2 seconds)
- **PERF-003:** User interface shall remain responsive during transformation execution
- **PERF-004:** Memory usage shall be optimized for large SDT structures

### 5.2 Platform Independence
- **PLAT-001:** The system shall run on Windows 2000 without code modifications
- **PLAT-002:** The system shall run on Solaris without code modifications
- **PLAT-003:** The system shall run on Linux without code modifications

### 5.3 Usability
- **USAB-001:** Interface shall be intuitive for expert transformation system users
- **USAB-002:** Minimal help system required due to user expertise
- **USAB-003:** Consistent interface behavior across all supported platforms

### 5.4 Reliability
- **RELI-001:** System shall handle transformation execution failures gracefully
- **RELI-002:** System shall recover from display of corrupt SDT structures
- **RELI-003:** No data loss during normal operation

### 5.5 Maintainability
- **MAIN-001:** Modular design to allow independent updates
- **MAIN-002:** Clear separation between GUI and transformation logic

## 6. Constraints, Assumptions & Dependencies

### 6.1 Constraints
- Must use Java for implementation
- Single-user operation only
- Requires HATS-SML version 2.0 availability by October 2001
- Must run on same system as HATS-SML

### 6.2 Assumptions
- Users have JVM and ML interpreter installed
- Target systems have hierarchical file systems
- Users possess transformation system expertise
- HATS-SML provides reliable transformation services

### 6.3 Dependencies
- **HATS-SML 2.0:** Critical dependency for transformation execution
- **JVM Availability:** Required for system execution
- **ML Interpreter:** Required for HATS-SML operation

## 7. Acceptance Criteria

### 7.1 Critical Success Factors
- **CSF-001:** Platform independence across all specified operating systems
- **CSF-002:** Meeting SDT display performance targets
- **CSF-003:** Support for concurrent operations during transformations

### 7.2 Acceptance Tests
- **AT-001:** Verify application launches and operates on Windows 2000, Solaris, and Linux
- **AT-002:** Measure and verify SDT display performance with 10,000 and 1,000,000 node structures
- **AT-003:** Demonstrate concurrent user operations during transformation execution
- **AT-004:** Validate all functional requirements through test scenarios
- **AT-005:** Verify integration with HATS-SML version 2.0

### 7.3 Priority Classification
- **High Priority:** Platform independence, performance requirements, core functionality
- **Medium Priority:** Display configuration, search functionality
- **Low Priority:** Advanced visualization features
