## 1 Introduction

### 1.1 Purpose
This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for the Tarrant County Indigent Defense Management System (IDMS). The system will manage court-appointed defense services for indigent defendants in Tarrant County, Texas, ensuring compliance with Texas legal requirements while streamlining defense coordination processes.

### 1.2 Scope
The IDMS shall provide comprehensive management of court-appointed defense services including:

**In-Scope:**
- Request submission for court-appointed counsel
- Attorney appointment processing and tracking
- Defendant-attorney contact tracking and reporting
- Case filing coordination with District Attorney
- Court scheduling and management
- Attorney compensation request processing
- Attorney appointment rotation list management
- Texas Fair Defense Act compliance reporting

**Out-of-Scope:**
- Financial management beyond attorney payment processing
- Case disposition tracking and management
- Legal representation decision-making
- Comprehensive accounting system functionality

## 2 Overall Description

### 2.1 Product Perspective
The IDMS is a component of Tarrant County's Integrated Justice Information System (IJIS) initiative. The system replaces manual processes for indigent defense coordination and integrates with existing county justice systems to enable seamless data flow across agencies.

### 2.2 Product Functions
The system shall provide the following core functionalities:

1. **Counsel Request Management** - Submit and process requests for court-appointed counsel
2. **Appointment Processing** - Manage attorney assignments and rotation lists
3. **Contact Tracking** - Monitor and report defendant-attorney contacts
4. **Case Coordination** - Coordinate with District Attorney on case filings
5. **Court Scheduling** - Manage court settings and appearances
6. **Compensation Processing** - Handle attorney payment requests and approvals
7. **Compliance Reporting** - Generate reports required by Texas Fair Defense Act

### 2.3 User Characteristics

| User Role | Responsibilities | Technical Proficiency |
|-----------|------------------|----------------------|
| Office of Attorney Appointments Staff | Manage counsel requests, appointments, compensation | Intermediate computer skills |
| Defense Attorneys | Submit contact logs, request payments, update availability | Basic to intermediate computer skills |
| Magistrates/Court Coordinators | Submit indigency requests, set court dates, confirm status | Intermediate computer skills |
| District Attorney Staff | File charges, notify case decisions | Intermediate computer skills |

### 2.4 Operating Environment
- **Platform**: Web-based application accessible via county network
- **Integration**: Must interface with Court Case Management System and DA Electronic Filing System
- **Security**: Must comply with Texas DITR security standards
- **Browser Support**: Current versions of major browsers (Chrome, Firefox, Edge)

### 2.5 Design and Implementation Constraints
- Must comply with Texas UETA and DITR guidelines for electronic transactions
- Must integrate with existing Court Case Management System architecture
- Must adhere to Texas Code of Criminal Procedure requirements
- Must maintain data consistency with external justice systems

## 3 System Features

### 3.1 Counsel Request Management

#### 3.1.1 Description
The system shall process requests for court-appointed counsel submitted by magistrates and court coordinators, ensuring all requests are processed within 24 hours of submission.

#### 3.1.2 Functional Requirements

**FR-001: Request Submission**
```markdown
- **Priority**: High
- **Description**: Magistrates shall be able to submit indigency requests electronically
- **Inputs**: Defendant information, case details, indigency determination
- **Processing**: Validate required fields, assign unique case identifier
- **Outputs**: Confirmed request with tracking number, system timestamp
```

**FR-002: Request Processing**
```markdown
- **Priority**: High
- **Description**: OAA staff shall process requests and assign attorneys within 24 hours
- **Inputs**: Request details, attorney availability, rotation list
- **Processing**: Check attorney rotation, assign qualified attorney, notify parties
- **Outputs**: Attorney assignment, notification to all parties, status update
```

### 3.2 Attorney Appointment and Contact Tracking

#### 3.2.1 Description
The system shall manage attorney appointments and track initial contact with defendants, ensuring contact occurs within one working day of appointment.

#### 3.2.2 Functional Requirements

**FR-010: Appointment Management**
```markdown
- **Priority**: High
- **Description**: Maintain and update attorney appointment rotation lists
- **Inputs**: Attorney qualifications, availability, case types
- **Processing**: Rotate assignments based on established criteria and availability
- **Outputs**: Updated rotation lists, assignment records
```

**FR-011: Contact Tracking**
```markdown
- **Priority**: High
- **Description**: Track and confirm first attorney-defendant contact
- **Inputs**: Contact date/time, method, outcome
- **Processing**: Validate contact occurs within 1 working day, flag exceptions
- **Outputs**: Contact confirmation, exception reports
```

### 3.3 Case Filing Coordination

#### 3.3.1 Description
The system shall coordinate case filing decisions with the District Attorney's office and manage related communications.

#### 3.3.2 Functional Requirements

**FR-020: DA Coordination**
```markdown
- **Priority**: Medium
- **Description**: Facilitate communication with DA regarding charge filings
- **Inputs**: Case information, filing decisions, charge details
- **Processing**: Route information to appropriate parties, track responses
- **Outputs**: Case status updates, notification records
```

### 3.4 Court Scheduling Management

#### 3.4.1 Description
The system shall manage court settings and appearances for defendants with appointed counsel.

#### 3.4.2 Functional Requirements

**FR-030: Scheduling Management**
```markdown
- **Priority**: Medium
- **Description**: Schedule and track court appearances and settings
- **Inputs**: Court dates, appearance types, participant availability
- **Processing**: Check conflicts, send notifications, track attendance
- **Outputs**: Court calendars, appearance records, notification logs
```

### 3.5 Compensation Processing

#### 3.5.1 Description
The system shall process attorney compensation requests and approvals, ensuring completion within 24 hours of request submission.

#### 3.5.2 Functional Requirements

**FR-040: Payment Request**
```markdown
- **Priority**: High
- **Description**: Attorneys shall submit compensation requests electronically
- **Inputs**: Hours worked, expenses, case information
- **Processing**: Validate against case records and rate schedules
- **Outputs**: Payment request record, validation results
```

**FR-041: Payment Approval**
```markdown
- **Priority**: High
- **Description**: OAA staff shall review and approve compensation requests
- **Inputs**: Payment requests, approval authority, budget constraints
- **Processing**: Verify eligibility, check limits, approve/deny with reasons
- **Outputs**: Approval decisions, payment records, denial explanations
```

### 3.6 Compliance Reporting

#### 3.6.1 Description
The system shall generate compliance reports required by the Texas Fair Defense Act.

#### 3.6.2 Functional Requirements

**FR-050: Report Generation**
```markdown
- **Priority**: High
- **Description**: Generate TFDA compliance reports on demand and scheduled basis
- **Inputs**: Case data, appointment records, contact logs, time metrics
- **Processing**: Aggregate data, calculate metrics, format according to state requirements
- **Outputs**: Compliance reports, exception summaries, performance metrics
```

## 4 External Interface Requirements

### 4.1 Software Interfaces

**SI-001: Court Case Management System**
```markdown
- **Interface Type**: REST API / Web Services
- **Purpose**: Exchange case data and custody status information
- **Data Elements**: Case numbers, defendant information, hearing dates, custody status
- **Frequency**: Real-time for critical updates, batch for data synchronization
```

**SI-002: District Attorney Electronic Case Filing System**
```markdown
- **Interface Type**: REST API / Web Services
- **Purpose**: Coordinate charge filings and case decisions
- **Data Elements**: Charge information, filing decisions, case dispositions
- **Frequency**: Real-time updates as filings occur
```

**SI-003: External Accounting Systems**
```markdown
- **Interface Type**: Batch File Transfer / API
- **Purpose**: Process compensation payments
- **Data Elements**: Payment amounts, attorney information, approval data
- **Frequency**: Daily batch processing
```

### 4.2 Hardware Interfaces
- Standard web browser interface accessible via county network
- No specialized hardware requirements beyond standard county workstations

### 4.3 Communications Interfaces
- HTTPS for all web communications
- Email notifications for status updates and alerts
- System-to-system web services for integration points

## 5 Non-Functional Requirements

### 5.1 Performance Requirements

**PER-001: Processing Time**
```markdown
- **Requirement**: All counsel requests shall be processed within 24 hours of submission
- **Measurement**: Time from request submission to attorney assignment
- **Target**: 100% compliance with 24-hour window
```

**PER-002: Contact Confirmation**
```markdown
- **Requirement**: First attorney contact shall be confirmed within 1 working day of appointment
- **Measurement**: Time from appointment to contact confirmation
- **Target**: 95% compliance with 1-working-day requirement
```

**PER-003: Compensation Processing**
```markdown
- **Requirement**: Compensation approvals shall be completed within 24 hours of request
- **Measurement**: Time from payment request submission to approval decision
- **Target**: 100% compliance with 24-hour window
```

### 5.2 Security Requirements

**SEC-001: Data Protection**
```markdown
- **Requirement**: All sensitive defendant data shall be encrypted in transit and at rest
- **Standard**: Compliance with Texas DITR security guidelines
- **Implementation**: AES-256 encryption for data at rest, TLS 1.2+ for data in transit
```

**SEC-002: Access Control**
```markdown
- **Requirement**: Role-based access control with least privilege principles
- **Implementation**: User authentication via county Active Directory, role-based permissions
```

### 5.3 Compliance Requirements

**COM-001: Legal Compliance**
```markdown
- **Requirement**: All electronic transactions shall comply with Texas UETA
- **Verification**: Legal review of transaction processes and records
```

**COM-002: Reporting Compliance**
```markdown
- **Requirement**: Reporting shall meet Texas Fair Defense Act compliance metrics
- **Verification**: Validation against TFDA reporting requirements
```

### 5.4 Reliability Requirements
- System availability: 99.5% during business hours (7:00 AM - 7:00 PM CT)
- Data backup: Daily incremental, weekly full backups
- Recovery time objective: 4 hours for critical system restoration

## 6 Constraints, Assumptions & Dependencies

### 6.1 Legal Constraints
- Must comply with Texas Code of Criminal Procedure Articles 1.051, 15.17, 26.04–26.052
- Must adhere to Texas Fair Defense Act requirements
- Must maintain compliance with Texas UETA for electronic records

### 6.2 Technical Constraints
- Must integrate with existing Court Case Management System architecture
- Must maintain compatibility with DA Electronic Case Filing System interfaces
- Must use county-standard security and authentication protocols

### 6.3 Assumptions
- Existing Court Case Management System provides accurate case data
- External systems maintain required availability and performance levels
- Users have adequate training and system access

### 6.4 Dependencies
- Successful integration with Court Case Management System
- Availability of DA Electronic Case Filing System interfaces
- County network infrastructure supporting system requirements

## 7 Acceptance Criteria

### 7.1 Legal Compliance Acceptance
- All system processes demonstrate compliance with Texas CCP Articles 1.051, 15.17, 26.04–26.052
- Reporting functionality meets all Texas Fair Defense Act requirements
- Electronic transactions comply with Texas UETA and DITR guidelines

### 7.2 Performance Acceptance
- 100% of test counsel requests processed within 24-hour window
- 95% of test attorney contacts confirmed within 1 working day
- 100% of test compensation approvals completed within 24 hours

### 7.3 Integration Acceptance
- Successful bidirectional data exchange with Court Case Management System
- Reliable interface functionality with DA Electronic Case Filing System
- Accurate data transfer to external accounting systems

### 7.4 User Acceptance
- All user roles can complete assigned tasks efficiently
- System interfaces are intuitive and require minimal training
- Reporting functions meet operational needs of all stakeholder groups
