## 1 Introduction

### 1.1 Purpose
This Software Requirements Specification document defines the functional and non-functional requirements for the Tactical Control System (TCS). The TCS provides comprehensive command and control capabilities for Predator and Outrider Unmanned Aerial Vehicles (UAVs) across multiple interaction levels.

### 1.2 Scope
The TCS encompasses software systems for UAV command and control across five interaction levels:
- **Level 1**: Receive/process UAV payload data
- **Level 2**: Direct/receive UAV payload data
- **Level 3**: Direct/receive UAV payload and flight path
- **Level 4**: Launch and recover UAV
- **Level 5**: Full UAV control from takeoff to landing

**Exclusions**: UAV hardware components, full HAE (High Altitude Endurance) UAV operations beyond payload data receipt.

## 2 Overall Description

### 2.1 Product Perspective
The TCS serves as a joint-service common control interface replacing multiple proprietary UAV control systems. It integrates with existing military C4I infrastructure and operates within the DII/COE framework.

### 2.2 Product Functions
- Mission planning and management
- Real-time UAV control and monitoring
- Payload data processing and exploitation
- Targeting support
- C4I system integration

### 2.3 User Characteristics
**Primary Users:**
- **Military Operators**: Trained personnel responsible for mission planning, UAV control, and payload operation
- **System Maintainers**: Technical personnel performing system maintenance, diagnostics, and repairs

### 2.4 Operating Modes
1. **Normal Operations**: Full system functionality for live mission execution
2. **Training Mode**: Simulation and training without affecting live operations
3. **Maintenance Mode**: System diagnostics and maintenance functions

### 2.5 Constraints
- Must comply with DII/COE, JTA, and CIGSS standards
- Must support all five UAV interaction levels
- Must use standard DoD components where available
- Must interface with specified C4I systems per implementation schedule

## 3 System Features

### 3.1 Mission Planning

#### 3.1.1 Description
Create, modify, and manage comprehensive UAV mission plans including flight routes, payload configurations, and communication parameters.

#### 3.1.2 Requirements
- **TCS-MP-001**: The system shall allow creation of flight routes with waypoints and altitude constraints
- **TCS-MP-002**: The system shall support payload configuration for EO, IR, and SAR sensors
- **TCS-MP-003**: The system shall enable communication parameter setup for LOS and SATCOM links
- **TCS-MP-004**: The system shall validate mission plans against operational constraints

### 3.2 Mission Control & Monitoring

#### 3.2.1 Description
Real-time control and monitoring of UAV platforms, payload systems, and data links across all five interaction levels.

#### 3.2.2 Requirements
- **TCS-MC-001**: The system shall provide real-time UAV telemetry display
- **TCS-MC-002**: The system shall enable direct UAV flight control (Level 5)
- **TCS-MC-003**: The system shall support payload operation and control
- **TCS-MC-004**: The system shall monitor and manage data link status

### 3.3 Payload Product Management

#### 3.3.1 Description
Process, display, and exploit imagery data from EO, IR, and SAR payload sensors.

#### 3.3.2 Requirements
- **TCS-PPM-001**: The system shall display real-time EO/IR/SAR imagery
- **TCS-PPM-002**: The system shall provide basic image enhancement tools
- **TCS-PPM-003**: The system shall support image annotation and measurement
- **TCS-PPM-004**: The system shall manage image storage and retrieval

### 3.4 Targeting

#### 3.4.1 Description
Develop target coordinates and estimate targeting accuracy based on sensor data.

#### 3.4.2 Requirements
- **TCS-TGT-001**: The system shall calculate target coordinates from sensor data
- **TCS-TGT-002**: The system shall estimate targeting accuracy based on sensor type and conditions
- **TCS-TGT-003**: The system shall generate targeting reports compatible with C4I systems

### 3.5 C4I System Interface

#### 3.5.1 Description
Interface with external C4I systems for tasking, data sharing, and information dissemination.

#### 3.5.2 Requirements
- **TCS-C4I-001**: The system shall receive mission tasking from external C4I systems
- **TCS-C4I-002**: The system shall share mission data with ASAS, AFATDS, and JSTARS
- **TCS-C4I-003**: The system shall disseminate products to authorized C4I systems

## 4 External Interface Requirements

### 4.1 Hardware Interfaces

| Interface Type | Specification | Purpose |
|---------------|---------------|---------|
| Data Terminals | LOS/SATCOM compatible | UAV communications |
| Power Supply | Standard military power sources | System operation |
| External Storage | Removable media interfaces | Data storage/transfer |
| Printers | Standard military printer interfaces | Hardcopy output |

### 4.2 Software Interfaces

| System | Interface Standard | Purpose |
|--------|-------------------|---------|
| ASAS | DII/COE compliant | Battlefield intelligence |
| AFATDS | DII/COE compliant | Fire support coordination |
| JSTARS | DII/COE compliant | Ground surveillance |
| Mission Planners | Service-specific standards | Mission planning integration |

### 4.3 Communication Interfaces
- **LOS Data Links**: Real-time line-of-sight communication with UAVs
- **SATCOM**: Beyond-line-of-sight satellite communication
- **Network Interfaces**: TCP/IP for C4I system integration

## 5 Non-Functional Requirements

### 5.1 Performance Requirements

| Parameter | Requirement |
|-----------|-------------|
| System Startup (Normal) | ≤ 60 seconds |
| System Startup (Recovery) | ≤ 45 seconds |
| Memory Utilization | ≤ 50% of total capacity |
| System Throughput | ≤ 50% of maximum capability |
| Data Processing | Real-time for sensor data streams |

### 5.2 Reliability

| Metric | Requirement |
|--------|-------------|
| MTBF | As specified in Predator/Outrider ORDs |
| MTTR | As specified in Predator/Outrider ORDs |
| Availability (Ao) | As specified in Predator/Outrider ORDs |

### 5.3 Security
- **TCS-SEC-001**: The system shall comply with COMSEC requirements for classified data
- **TCS-SEC-002**: The system shall implement role-based access control
- **TCS-SEC-003**: The system shall maintain audit trails of all critical operations

### 5.4 Maintainability
- **TCS-MNT-001**: The system shall provide comprehensive diagnostic capabilities
- **TCS-MNT-002**: The system shall support modular component replacement
- **TCS-MNT-003**: The system shall include built-in test (BIT) capabilities

## 6 Other Requirements

### 6.1 Compliance Requirements
- DII/COE standards compliance
- Joint Technical Architecture (JTA) compliance
- CIGSS standards compliance
- Military communication security standards

### 6.2 Priority and Acceptance Criteria

#### 6.2.1 Critical Priorities
1. Support for all five UAV interaction levels (Level 5 - full control is critical)
2. Integration with specified C4I systems
3. Compliance with Predator/Outrider ORDs for reliability and availability

#### 6.2.2 Acceptance Approach
- Verification of all specified requirements
- Successful integration testing with C4I systems
- Demonstration of compliance with Predator/Outrider ORDs
- Validation of all five interaction levels functionality

### 6.3 Assumptions and Dependencies
- Availability of standard DoD components
- Compliance with evolving DII/COE standards
- Successful integration with legacy C4I systems
- Adherence to implementation schedule for interface development
