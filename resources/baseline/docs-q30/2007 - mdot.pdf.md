## 1 Introduction

### 1.1 Purpose
This Software Requirements Specification document describes the functional and non-functional requirements for the Data Utility Analysis Platform (DUAP). The DUAP system is a prototype research tool designed to evaluate Vehicle Infrastructure Integration (VII) data utility in enhancing transportation safety, mobility, and asset management for MDOT.

### 1.2 Scope
The DUAP system processes probe vehicle, traffic, weather, and road condition data from multiple sources to transform raw data into actionable insights. The system serves exclusively as a research vehicle and does not support operational traffic management or public-facing services beyond research demonstrations.

**In-Scope:**
- VII data collection and integration
- Real-time data processing and analytics
- Research-focused data visualization
- Prototype system deployment

**Out-of-Scope:**
- Operational traffic management
- Public-facing services
- Production-grade system reliability
- 24/7 operational support

## 2 Overall Description

### 2.1 Product Perspective
DUAP operates within MDOT's existing transportation technology ecosystem, integrating with:
- VII network infrastructure
- MITS Center traffic management systems
- RWIS and Clarus weather data systems
- OEM fleet data sources

The system serves as a research prototype to assess data integration feasibility before potential operational deployment.

### 2.2 Product Functions

| Function ID | Function Description | Priority |
|-------------|---------------------|----------|
| FUNC-001 | Collect probe vehicle data (SAE J2735) | H |
| FUNC-002 | Cache dynamic data with 1-week retention | H |
| FUNC-003 | Derive traffic/road conditions via computational services | H |
| FUNC-004 | Archive persistent data for long-term analysis | M |
| FUNC-005 | Publish output in SAE J2354 format | H |
| FUNC-006 | Provide web-based data visualization | M |

### 2.3 User Characteristics

| User Role | Primary Responsibilities | Technical Expertise |
|-----------|-------------------------|-------------------|
| Transportation Operator | Real-time incident response, traffic management | High |
| Maintenance Staff | Road condition monitoring, repair prioritization | Medium |
| Emergency Responder | Access to real-time incident data | Medium |
| Researcher | Data analysis, research validation | High |

### 2.4 Constraints
- **Privacy Compliance**: All probe data must be anonymized per MDOT privacy policies
- **Data Ownership**: Third-party data ownership limits may restrict integration
- **Prototype Nature**: System is not intended for operational use
- **Dependencies**: Success depends on VII network data availability and OEM participation

### 2.5 Assumptions and Dependencies
- VII network infrastructure will provide continuous data feeds
- OEM partners will supply probe vehicle data as agreed
- Existing MDOT systems (MITS, RWIS) will maintain current interfaces
- Research team will have appropriate access to required systems

## 3 System Features

### 3.1 Data Collection Module [H]

#### 3.1.1 Description
Collects probe vehicle data from VII networks and OEM fleets in SAE J2735 format.

#### 3.1.2 Requirements
- **REQ-001**: System shall ingest probe vehicle data from VII networks
- **REQ-002**: System shall accept OEM fleet data in standardized formats
- **REQ-003**: System shall validate incoming data against SAE J2735 schema
- **REQ-004**: System shall perform data quality checks on all incoming data

### 3.2 Data Caching Module [H]

#### 3.2.1 Description
Provides temporary storage for raw and derived data with 1-week retention for immediate processing.

#### 3.2.2 Requirements
- **REQ-005**: System shall cache raw probe data for minimum 7 days
- **REQ-006**: System shall cache derived data products for minimum 7 days
- **REQ-007**: System shall support configurable cache retention policies
- **REQ-008**: System shall provide cache performance monitoring

### 3.3 Computational Services Module [H]

#### 3.3.1 Description
Derives traffic and road conditions through analytical algorithms including incident detection and travel time calculation.

#### 3.3.2 Requirements
- **REQ-009**: System shall detect traffic incidents from probe data
- **REQ-010**: System shall calculate travel time estimates
- **REQ-011**: System shall assess road conditions from multiple data sources
- **REQ-012**: System shall generate derived metrics for safety analysis

### 3.4 Data Archiving Module [M]

#### 3.4.1 Description
Stores persistent raw and derived data for long-term research analysis.

#### 3.4.2 Requirements
- **REQ-013**: System shall archive raw data for research purposes
- **REQ-014**: System shall archive derived data products
- **REQ-015**: System shall support data retrieval for analysis
- **REQ-016**: System shall maintain data integrity during archival

### 3.5 Data Publishing Module [H]

#### 3.5.1 Description
Publishes processed output in SAE J2354 format for consumption by external systems.

#### 3.5.2 Requirements
- **REQ-017**: System shall format output per SAE J2354 standards
- **REQ-018**: System shall publish data to authorized external systems
- **REQ-019**: System shall support configurable publishing intervals
- **REQ-020**: System shall log all data publishing activities

### 3.6 Presentation Services Module [M]

#### 3.6.1 Description
Provides web-based visualization of traffic and weather data for research demonstration purposes.

#### 3.6.2 Requirements
- **REQ-021**: System shall provide web-based data visualization
- **REQ-022**: System shall display real-time traffic conditions
- **REQ-023**: System shall present weather and road condition data
- **REQ-024**: System shall support role-based access to visualization features

## 5 Non-Functional Requirements

### 5.1 Performance Requirements

| Requirement | Metric | Priority |
|-------------|--------|----------|
| Data Processing Latency | ≤ 5 minutes from receipt to availability | H |
| System Availability | 95% during research operations | M |
| Data Throughput | Support expected VII data volumes | H |
| Cache Performance | Sub-second response for cached data | M |

### 5.2 Safety Requirements
- All probe data must be anonymized to protect privacy
- System outputs must be clearly labeled as research-grade
- Access controls must prevent unauthorized data access

### 5.3 Security Requirements
- Compliance with MDIT software security standards
- Role-based access control for all system functions
- Audit logging for data access and modifications
- Secure data transmission for all external interfaces

### 5.4 Software Quality Attributes
- **Maintainability**: Modular design for research modifications
- **Reliability**: Robust error handling for data processing
- **Usability**: Intuitive interface for research personnel
- **Scalability**: Architecture supporting potential future expansion
